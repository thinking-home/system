# plugins/scripts/http-api Specification

## Purpose

Предоставляет HTTP API для управления сохранёнными сценариями (CRUD и запуск) и подписками сценариев на сценарные события, поверх контракта `plugins/web-server/http-resources` и `plugins/scripts/script-execution`/`plugins/scripts/script-events`.

## Requirements

### Requirement: Получение списка сценариев
Динамический ресурс `/api/scripts/web-api/list` SHALL без параметров возвращать список всех сохранённых сценариев, каждый — с полями `id` и `name`.

#### Scenario: Запрос списка сценариев
- **WHEN** выполняется запрос `/api/scripts/web-api/list`
- **THEN** в ответе возвращается список сохранённых сценариев с их `id` и `name`

### Requirement: Получение сценария
Динамический ресурс `/api/scripts/web-api/get` SHALL принимать обязательный параметр `id` и возвращать объект с полями `id`, `name`, `body` сценария с этим идентификатором. Если сценарий с указанным `id` не найден, SHALL быть возвращён код ошибки 500.

#### Scenario: Запрос существующего сценария
- **WHEN** выполняется запрос `/api/scripts/web-api/get` с `id` существующего сценария
- **THEN** в ответе возвращается объект с `id`, `name` и `body` этого сценария

#### Scenario: Запрос несуществующего сценария
- **WHEN** выполняется запрос `/api/scripts/web-api/get` с `id`, для которого нет сохранённого сценария
- **THEN** клиент получает ответ с кодом 500

### Requirement: Сохранение сценария
Динамический ресурс `/api/scripts/web-api/save` SHALL принимать обязательные параметры `name` и `body`, а также опциональный параметр `id`. Если `id` не передан, SHALL быть создан новый сценарий с новым идентификатором; если `id` передан, SHALL быть обновлён существующий сценарий с этим идентификатором (его `name` и `body` заменяются переданными значениями). В ответе SHALL быть возвращён объект `{ scriptId }` с идентификатором сохранённого сценария.

#### Scenario: Создание нового сценария
- **WHEN** выполняется запрос `/api/scripts/web-api/save` с `name` и `body`, без `id`
- **THEN** создаётся новый сценарий с этими `name` и `body`, а в ответе возвращается его новый `scriptId`

#### Scenario: Обновление существующего сценария
- **WHEN** выполняется запрос `/api/scripts/web-api/save` с `id` существующего сценария и новыми `name`/`body`
- **THEN** сценарий с этим `id` обновляется переданными `name` и `body`, а в ответе возвращается тот же `scriptId`

### Requirement: Удаление сценария
Динамический ресурс `/api/scripts/web-api/delete` SHALL принимать обязательный параметр `id` и удалять сценарий с этим идентификатором, возвращая пустой ответ. Если сценарий с указанным `id` не найден, SHALL быть возвращён код ошибки 500.

#### Scenario: Удаление существующего сценария
- **WHEN** выполняется запрос `/api/scripts/web-api/delete` с `id` существующего сценария
- **THEN** сценарий удаляется, клиент получает пустой ответ без ошибки

#### Scenario: Удаление несуществующего сценария
- **WHEN** выполняется запрос `/api/scripts/web-api/delete` с `id`, для которого нет сохранённого сценария
- **THEN** клиент получает ответ с кодом 500

### Requirement: Запуск сценария
Динамический ресурс `/api/scripts/web-api/execute` SHALL принимать обязательный параметр `id`, выполнять сохранённый сценарий с этим идентификатором и возвращать клиенту значение, которое сценарий вернул через `return` (или `null`, если возврата не было). Если выполнение сценария завершилось ошибкой, клиенту SHALL быть возвращён `null` без признака ошибки; текст ошибки записывается в лог системы.

#### Scenario: Запуск сценария с возвращаемым значением
- **WHEN** выполняется запрос `/api/scripts/web-api/execute` с `id` сценария, который возвращает значение через `return`
- **THEN** в ответе возвращается это значение

#### Scenario: Запуск сценария, завершившегося ошибкой
- **WHEN** выполняется запрос `/api/scripts/web-api/execute` с `id` сценария, выполнение которого завершается ошибкой
- **THEN** клиент получает `null` без признака ошибки в ответе

### Requirement: Список зарегистрированных событий
Динамический ресурс `/api/scripts/web-api/events/list` SHALL без параметров возвращать список зарегистрированных сценарных событий (только их имена) и константы пользовательского события — его имя (`userEvent.name`) и ключ meta, в котором передаётся динамическое имя пользовательского события (`userEvent.metaKey`).

#### Scenario: Запрос списка событий
- **WHEN** выполняется запрос `/api/scripts/web-api/events/list`
- **THEN** в ответе возвращается список зарегистрированных событий и объект `userEvent` с именем пользовательского события и ключом meta

### Requirement: Список подписок на события
Динамический ресурс `/api/scripts/web-api/subscription/list` SHALL без параметров возвращать список всех подписок сценариев на сценарные события, каждая — с `id` подписки, `scriptId` и `scriptName` подписанного сценария, `eventName` события и `metaFilter` (или `null`, если фильтра нет).

#### Scenario: Запрос списка подписок
- **WHEN** выполняется запрос `/api/scripts/web-api/subscription/list`
- **THEN** в ответе возвращается список подписок с `id`, `scriptId`, `scriptName`, `eventName` и `metaFilter`

### Requirement: Добавление подписки
Динамический ресурс `/api/scripts/web-api/subscription/add` SHALL принимать обязательные параметры `scriptId` и `eventName`, а также опциональный параметр `metaFilter` (в формате query string). Перед сохранением `metaFilter` SHALL быть приведён к каноническому виду. Пустой (или отсутствующий) фильтр SHALL сохраняться как `null`. В ответе SHALL быть возвращён объект `{ subscriptionId }` с идентификатором созданной подписки.

#### Scenario: Добавление подписки без фильтра
- **WHEN** выполняется запрос `/api/scripts/web-api/subscription/add` с `scriptId` и `eventName`, без `metaFilter`
- **THEN** создаётся подписка с `metaFilter = null`, а в ответе возвращается её `subscriptionId`

#### Scenario: Добавление подписки с фильтром
- **WHEN** выполняется запрос `/api/scripts/web-api/subscription/add` с `scriptId`, `eventName` и `metaFilter`
- **THEN** создаётся подписка с фильтром, приведённым к каноническому виду, а в ответе возвращается её `subscriptionId`

### Requirement: Удаление подписки
Динамический ресурс `/api/scripts/web-api/subscription/delete` SHALL принимать обязательный параметр `subscriptionId` и удалять подписку с этим идентификатором, возвращая пустой ответ. Если подписка с указанным `subscriptionId` не найдена, SHALL быть возвращён код ошибки 500.

#### Scenario: Удаление существующей подписки
- **WHEN** выполняется запрос `/api/scripts/web-api/subscription/delete` с `subscriptionId` существующей подписки
- **THEN** подписка удаляется, клиент получает пустой ответ без ошибки

#### Scenario: Удаление несуществующей подписки
- **WHEN** выполняется запрос `/api/scripts/web-api/subscription/delete` с `subscriptionId`, для которого нет подписки
- **THEN** клиент получает ответ с кодом 500
