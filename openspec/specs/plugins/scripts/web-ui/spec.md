# plugins/scripts/web-ui Specification

## Purpose

Добавляет в веб-интерфейс разделы для работы со сценариями: список сценариев, редактор и подписки на сценарные события, — использующие HTTP API `plugins/scripts/http-api`.

## Requirements

### Requirement: Зависимость от HTTP API сценариев
`Scripts.WebUi` SHALL получать все данные о сценариях, событиях и подписках через HTTP API `plugins/scripts/http-api`; для корректной работы разделов `Scripts.WebUi` SHALL быть подключён вместе с плагином, предоставляющим этот API.

#### Scenario: Раздел использует HTTP API сценариев
- **WHEN** пользователь открывает любой из разделов `Scripts.WebUi`
- **THEN** данные для раздела запрашиваются через HTTP API `/api/scripts/web-api/*`

### Requirement: Раздел списка сценариев
Страница `/scripts` SHALL отображать список сохранённых сценариев и SHALL предоставлять переход к редактированию сценария, к созданию нового сценария, к удалению существующего и к разделу подписок на события.

#### Scenario: Открытие списка сценариев
- **WHEN** пользователь открывает `/scripts`
- **THEN** отображается список сохранённых сценариев с возможностью перейти к редактированию, созданию, удалению сценария и к подпискам на события

### Requirement: Раздел редактора сценария
Страница `/scripts/edit` без параметра `id` SHALL открывать редактор нового сценария; с параметром `id` SHALL открывать редактор сохранённого сценария с этим идентификатором. Редактор SHALL позволять задать название и текст сценария, сохранить его, а для сохранённого сценария — выполнить его и увидеть возвращённое значение. Пока в редакторе есть несохранённые изменения, действие запуска сценария SHALL быть недоступно (выполняется сохранённый вариант сценария).

#### Scenario: Открытие редактора нового сценария
- **WHEN** пользователь открывает `/scripts/edit` без параметра `id`
- **THEN** открывается редактор для создания нового сценария

#### Scenario: Открытие редактора сохранённого сценария
- **WHEN** пользователь открывает `/scripts/edit?id={id}` с идентификатором сохранённого сценария
- **THEN** открывается редактор с названием и текстом этого сценария

#### Scenario: Запуск при наличии несохранённых изменений
- **WHEN** в редакторе есть несохранённые изменения текста или названия сценария
- **THEN** действие запуска сценария недоступно

### Requirement: Раздел подписок на события
Страница `/scripts/subscriptions` SHALL отображать список подписок сценариев на сценарные события и SHALL предоставлять добавление новой подписки и удаление существующей с подтверждением; редактирование существующей подписки не предусмотрено. При добавлении подписки название события SHALL выбираться из списка зарегистрированных событий (с поиском по названию), а фильтр по meta SHALL задаваться таблицей пар «ключ-значение». Если выбрано пользовательское событие (см. `plugins/scripts/script-events` — пользовательское событие), первая строка фильтра SHALL быть закреплена: её ключ — ключ meta пользовательского события, значение — имя события, удалить эту строку или изменить её ключ SHALL быть нельзя. Подписка на событие, отсутствующее в реестре зарегистрированных событий, SHALL по-прежнему отображаться в списке, с пометкой о том, что событие не зарегистрировано.

#### Scenario: Открытие списка подписок
- **WHEN** пользователь открывает `/scripts/subscriptions`
- **THEN** отображается список существующих подписок на сценарные события

#### Scenario: Добавление подписки на пользовательское событие
- **WHEN** пользователь добавляет подписку и выбирает пользовательское событие
- **THEN** первая строка таблицы фильтра закреплена с ключом meta пользовательского события и значением, равным введённому имени события, и её нельзя удалить или изменить ключ

#### Scenario: Подписка на незарегистрированное событие
- **WHEN** в списке подписок есть подписка на событие, которого нет среди зарегистрированных
- **THEN** подписка отображается в списке с пометкой, что событие не зарегистрировано

### Requirement: Редактор сценария на CodeMirror
Текст сценария в редакторе SHALL редактироваться в CodeMirror с подсветкой синтаксиса JavaScript, SHALL поддерживать светлую и тёмную цветовые схемы, переключающиеся вместе с интерфейсом, и SHALL использовать шрифт JetBrains Mono, отдаваемый со стороны плагина (не из внешнего источника).

#### Scenario: Переключение цветовой схемы интерфейса
- **WHEN** пользователь переключает цветовую схему веб-интерфейса
- **THEN** цветовая схема редактора сценария переключается вместе с интерфейсом

#### Scenario: Шрифт редактора отдаётся без внешнего источника
- **WHEN** отображается редактор сценария
- **THEN** используемый шрифт (JetBrains Mono) загружается с сервера плагина, а не из внешнего источника

### Requirement: Форма подписки в шторке
Форма добавления подписки SHALL открываться в шторке, выдвигающейся с правого края поверх страницы `/scripts/subscriptions`, а не на самой странице; список подписок SHALL оставаться на странице без изменений. Состав полей формы и поведение таблицы фильтра по meta SHALL оставаться прежними (см. требование «Раздел подписок на события»). Успешное добавление SHALL закрывать шторку и обновлять список; при ошибке добавления шторка SHALL оставаться открытой с введёнными данными. Закрытие шторки без сохранения (кнопкой отмены, кнопкой закрытия, клавишей Escape или кликом вне шторки) SHALL отбрасывать введённые данные без подтверждения; при следующем открытии форма SHALL быть пустой.

#### Scenario: Открытие формы новой подписки
- **GIVEN** открыта страница `/scripts/subscriptions`
- **WHEN** пользователь нажимает кнопку добавления новой подписки
- **THEN** справа открывается шторка с пустой формой подписки, а список подписок остаётся на странице

#### Scenario: Успешное добавление закрывает шторку
- **GIVEN** в шторке выбраны сценарий и событие
- **WHEN** пользователь добавляет подписку и сервер подтверждает сохранение
- **THEN** шторка закрывается, а новая подписка появляется в списке

#### Scenario: Ошибка добавления оставляет шторку открытой
- **GIVEN** открыта шторка с заполненной формой подписки
- **WHEN** добавление подписки завершается ошибкой
- **THEN** шторка остаётся открытой, введённые данные сохраняются, показывается уведомление об ошибке

#### Scenario: Закрытие шторки подписки без сохранения
- **GIVEN** в шторке выбраны сценарий и событие
- **WHEN** пользователь закрывает шторку без сохранения и открывает форму снова
- **THEN** форма пуста, а подписка не создана

### Requirement: Состояния списков сценариев и подписок
Страницы `/scripts` и `/scripts/subscriptions` SHALL отображать в области списка локализованное сообщение серым текстом с выравниванием по центру, когда соответствующий список пуст или его загрузка завершилась ошибкой. Пустое состояние SHALL показываться только после успешной загрузки пустого списка, а состояние ошибки SHALL показываться после ошибки любого запроса, без которого соответствующая страница не может быть отображена. Заголовок и доступные действия страницы SHALL оставаться видимыми; при ошибке SHALL также сохраняться уведомление об ошибке.

#### Scenario: Пустой список сценариев
- **WHEN** запрос списка сценариев успешно возвращает пустой список
- **THEN** в области списка отображается центрированное серое сообщение об отсутствии сценариев, а действия страницы остаются доступны

#### Scenario: Ошибка загрузки списка сценариев
- **WHEN** запрос списка сценариев завершается ошибкой
- **THEN** в области списка отображается центрированное серое сообщение об ошибке и показывается уведомление об ошибке

#### Scenario: Пустой список подписок
- **WHEN** запрос списка подписок успешно возвращает пустой список, а остальные данные страницы загружены
- **THEN** в области списка отображается центрированное серое сообщение об отсутствии подписок, а действие добавления подписки остаётся доступно

#### Scenario: Ошибка загрузки страницы подписок
- **WHEN** запрос подписок, сценариев или зарегистрированных событий завершается ошибкой
- **THEN** в области содержимого отображается центрированное серое сообщение об ошибке и показывается уведомление об ошибке

### Requirement: Пустое состояние редактора meta-фильтра
Редактор meta-фильтра в шторке новой подписки SHALL показывать центрированное серое сообщение об отсутствии правил, когда в фильтре нет ни закреплённой строки пользовательского события, ни добавленных пользователем строк. Действие добавления строки SHALL оставаться видимым и доступным.

#### Scenario: В фильтре нет правил
- **GIVEN** открыта шторка новой подписки и не выбрано пользовательское событие
- **WHEN** пользователь ещё не добавил ни одной строки meta-фильтра
- **THEN** редактор показывает центрированное серое сообщение об отсутствии правил и доступное действие добавления строки

#### Scenario: Добавление первого правила
- **GIVEN** редактор meta-фильтра показывает пустое состояние
- **WHEN** пользователь добавляет строку
- **THEN** пустое состояние скрывается и отображается редактируемая строка правила

### Requirement: Заголовок шторки подписки
Шторка новой подписки SHALL содержать ровно один семантический заголовок второго уровня для названия формы. Его размер шрифта, высота строки и насыщенность SHALL соответствовать оформлению заголовка второго уровня текущей темы Mantine и визуально выделять название относительно обычного текста шторки.

#### Scenario: Открытие шторки подписки с крупным заголовком
- **WHEN** пользователь открывает форму новой подписки
- **THEN** название формы отображается единственным заголовком второго уровня с оформлением `h2` текущей темы
