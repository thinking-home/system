# plugins/web-server/http-resources Specification

## Purpose

Предоставляет плагинам возможность обрабатывать HTTP-запросы: регистрировать статические и динамические ресурсы по URL и получать их содержимое через встроенный веб-сервер приложения.

## Requirements

### Requirement: Регистрация HTTP-обработчиков через атрибут
Метод плагина, помеченный атрибутом `ConfigureWebServer` и соответствующий по сигнатуре делегату `ConfigureWebServerDelegate` (один параметр — билдер конфигурации веб-сервера, без возвращаемого значения), SHALL быть вызван при инициализации веб-сервера с билдером, через который плагин регистрирует свои HTTP-ресурсы. Билдер собирается по всем плагинам приложения, независимо от того, в каком порядке относительно веб-сервера они будут инициализированы.

#### Scenario: Метод с атрибутом ConfigureWebServer вызывается при старте
- **WHEN** плагин объявляет метод с атрибутом `ConfigureWebServer`, соответствующий `ConfigureWebServerDelegate`
- **THEN** при инициализации веб-сервера этот метод вызывается один раз с билдером, через который плагин может зарегистрировать свои ресурсы

### Requirement: Уникальность URL среди зарегистрированных ресурсов
Каждый HTTP-ресурс (статический или динамический) SHALL быть зарегистрирован на уникальный URL в рамках приложения; повторная регистрация уже занятого URL SHALL приводить к ошибке при инициализации.

#### Scenario: Повторная регистрация того же URL
- **WHEN** два обработчика регистрируются на один и тот же URL
- **THEN** регистрация завершается ошибкой

### Requirement: Порт HTTP-сервера конфигурируется
Веб-сервер SHALL слушать HTTP-запросы на порту, заданном параметром `port` в конфигурации плагина; если параметр не задан, SHALL использоваться порт `41831` по умолчанию.

#### Scenario: Порт не задан в конфигурации
- **WHEN** параметр `port` отсутствует в конфигурации плагина
- **THEN** сервер слушает HTTP-запросы на порту `41831`

#### Scenario: Порт задан в конфигурации
- **WHEN** параметр `port` задан в конфигурации плагина
- **THEN** сервер слушает HTTP-запросы на этом порту

### Requirement: Статический ресурс отдаётся по URL
Зарегистрированный статический ресурс SHALL отдаваться на GET-запрос по своему URL с содержимым файла, встроенного в ресурсы указанной (или, если не указана явно, содержащей плагин) сборки, и с заданным content type. Ответ SHALL кэшироваться на сервере: заголовок `Cache-Control` в ответе SHALL указывать, что ответ приватный и допускает кэширование на заданный срок.

#### Scenario: Запрос зарегистрированного статического ресурса
- **WHEN** выполняется GET-запрос по URL, на котором зарегистрирован статический ресурс
- **THEN** ответ содержит данные встроенного файла с заданным content type и заголовком `Cache-Control`, разрешающим кэширование

### Requirement: Отдача предсжатых вариантов статического ресурса
Статический ресурс SHALL опционально сопровождаться предсжатыми (gzip и brotli) вариантами; при их наличии SHALL быть заданы оба варианта одновременно — регистрация ресурса, для которого указан только один из двух вариантов, SHALL приводить к ошибке. Если у ресурса есть предсжатые варианты, сервер SHALL выбирать вариант ответа по заголовку запроса `Accept-Encoding`, отдавая предпочтение brotli перед gzip; если ни одна из закодированных версий не поддерживается клиентом, SHALL отдаваться исходный (несжатый) файл. Ответ с предсжатыми вариантами SHALL включать заголовки `Content-Encoding` (для сжатого варианта) и `Vary: Accept-Encoding`.

#### Scenario: Регистрация ресурса только с одним из двух сжатых вариантов
- **WHEN** для статического ресурса указан gzip-вариант, но не указан brotli-вариант (или наоборот)
- **THEN** регистрация ресурса завершается ошибкой

#### Scenario: Клиент поддерживает и brotli, и gzip
- **WHEN** запрос содержит заголовок `Accept-Encoding` со значениями `br` и `gzip`, а ресурс зарегистрирован с обоими предсжатыми вариантами
- **THEN** сервер отдаёт brotli-вариант с заголовком `Content-Encoding: br`

#### Scenario: Клиент не поддерживает ни один из предсжатых вариантов
- **WHEN** запрос не содержит в `Accept-Encoding` ни одной из закодированных версий, зарегистрированных для ресурса
- **THEN** сервер отдаёт исходный (несжатый) файл

### Requirement: Динамический ресурс генерируется на каждый запрос
Зарегистрированный динамический ресурс SHALL при каждом запросе по своему URL вызывать обработчик, зарегистрированный для этого ресурса, передавая ему параметры запроса, и возвращать клиенту результат, сформированный обработчиком. Динамический ресурс SHALL опционально кэшироваться на сервере (по умолчанию не кэшируется); некэшируемый ответ SHALL сопровождаться заголовком `Cache-Control`, запрещающим кэширование.

#### Scenario: Запрос динамического ресурса вызывает обработчик
- **WHEN** выполняется запрос по URL, на котором зарегистрирован динамический ресурс
- **THEN** вызывается обработчик, зарегистрированный для этого URL, и клиенту возвращается результат, который он вернул

#### Scenario: Некэшируемый динамический ресурс
- **WHEN** динамический ресурс зарегистрирован без включённого кэширования
- **THEN** ответ на каждый запрос содержит заголовок `Cache-Control`, запрещающий кэширование

### Requirement: Чтение параметров запроса
Параметр запроса, запрошенный по имени, SHALL читаться и из строки запроса, и из данных отправленной формы; если значение присутствует в обоих источниках, SHALL возвращаться их объединение через запятую. Обязательный параметр, отсутствующий в запросе, SHALL приводить к ошибке с кодом `BadRequest` (400) без вызова обработчика.

#### Scenario: Параметр присутствует и в query, и в форме
- **WHEN** запрос передаёт значение одного и того же параметра и в query string, и в теле формы
- **THEN** обработчик получает объединённое значение — оба значения через запятую

#### Scenario: Обязательный параметр отсутствует
- **WHEN** обработчик запрашивает обязательный параметр, которого нет ни в query string, ни в форме
- **THEN** клиенту возвращается ответ с кодом 400 (Bad Request)

### Requirement: Обработка ошибок динамического обработчика
Если обработчик динамического ресурса генерирует исключение `HttpHandlerException`, клиенту SHALL быть возвращён код ответа, указанный в этом исключении (`BadRequest` = 400 или `Internal` = 500), без тела ответа. Любое другое необработанное исключение обработчика SHALL приводить к ответу с кодом 500 (Internal Server Error).

#### Scenario: Обработчик выбрасывает HttpHandlerException с кодом BadRequest
- **WHEN** обработчик динамического ресурса генерирует `HttpHandlerException` с кодом `BadRequest`
- **THEN** клиент получает ответ с кодом 400 без тела

#### Scenario: Обработчик выбрасывает произвольное исключение
- **WHEN** обработчик динамического ресурса генерирует исключение, отличное от `HttpHandlerException`
- **THEN** клиент получает ответ с кодом 500

### Requirement: Пустой результат обработчика
Если обработчик динамического ресурса возвращает пустой результат, ответ клиенту SHALL быть отправлен без тела и без ошибки.

#### Scenario: Обработчик возвращает пустой результат
- **WHEN** обработчик динамического ресурса возвращает пустое значение результата
- **THEN** клиенту отправляется ответ без тела, без ошибки

### Requirement: Запрос на незарегистрированный URL не обрабатывается веб-сервером плагинов
Если запрошенный URL не совпадает ни с одним зарегистрированным ресурсом, веб-сервер плагинов SHALL передать обработку запроса дальше по конвейеру приложения, не вмешиваясь в ответ.

#### Scenario: Запрос по незарегистрированному URL
- **WHEN** выполняется запрос по URL, для которого не зарегистрирован ни статический, ни динамический ресурс
- **THEN** запрос обрабатывается дальше стандартным конвейером приложения, а не веб-сервером плагинов
