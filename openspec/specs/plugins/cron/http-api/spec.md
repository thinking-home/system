# plugins/cron/http-api Specification

## Purpose

Предоставляет HTTP API для управления записями расписания `plugins/cron/task-scheduling` и для проверки и человекочитаемого описания выражений cron, поверх контракта `plugins/web-server/http-resources`.

## Requirements

### Requirement: Представление записи расписания в ответах API
Запись расписания в ответах HTTP API SHALL представляться объектом с полями `id`, `name`, `eventName`, `enabled`, `expression` и `description` — человекочитаемым описанием `expression` на языке системы (см. «Проверка и описание выражения»), или `null`, если выражение некорректно либо описание не удалось построить.

#### Scenario: Представление записи с корректным выражением
- **WHEN** запись расписания возвращается в ответе API
- **THEN** объект содержит `id`, `name`, `eventName`, `enabled`, `expression` и человекочитаемое `description` этого выражения

### Requirement: Получение списка записей расписания
Динамический ресурс `/api/cron/web-api/list` SHALL без параметров возвращать список всех записей расписания, упорядоченный по `name`.

#### Scenario: Запрос списка записей
- **WHEN** выполняется запрос `/api/cron/web-api/list`
- **THEN** в ответе возвращается список всех записей расписания, упорядоченный по названию

### Requirement: Получение записи расписания
Динамический ресурс `/api/cron/web-api/get` SHALL принимать обязательный параметр `id` и возвращать запись расписания с этим идентификатором. Если запись с указанным `id` не найдена, SHALL быть возвращён код ошибки 500.

#### Scenario: Запрос существующей записи
- **WHEN** выполняется запрос `/api/cron/web-api/get` с `id` существующей записи
- **THEN** в ответе возвращается эта запись расписания

#### Scenario: Запрос несуществующей записи
- **WHEN** выполняется запрос `/api/cron/web-api/get` с `id`, для которого нет записи расписания
- **THEN** клиент получает ответ с кодом 500

### Requirement: Сохранение записи расписания
Динамический ресурс `/api/cron/web-api/save` SHALL принимать обязательные параметры `name`, `enabled` и `expression`, а также опциональные параметры `id` и `eventName`. Если `id` не передан, SHALL быть создана новая запись с новым идентификатором; если `id` передан, SHALL быть обновлена существующая запись с этим идентификатором. Формат `expression` SHALL быть проверен тем же парсером, который исполняет расписание; если выражение некорректно, SHALL быть возвращён код ошибки 400, а запись SHALL не быть сохранена. После успешного сохранения кэш расписания SHALL быть сброшен (см. `plugins/cron/task-scheduling` — сброс кэша расписания), чтобы изменение вступило в силу. В ответе SHALL быть возвращён объект `{ taskId }` с идентификатором сохранённой записи.

#### Scenario: Создание новой записи с корректным выражением
- **WHEN** выполняется запрос `/api/cron/web-api/save` с `name`, `enabled`, корректным `expression`, без `id`
- **THEN** создаётся новая запись с этими данными, кэш расписания сбрасывается, а в ответе возвращается новый `taskId`

#### Scenario: Обновление существующей записи
- **WHEN** выполняется запрос `/api/cron/web-api/save` с `id` существующей записи и новыми данными
- **THEN** запись с этим `id` обновляется переданными данными, кэш расписания сбрасывается, а в ответе возвращается тот же `taskId`

#### Scenario: Сохранение с некорректным выражением
- **WHEN** выполняется запрос `/api/cron/web-api/save` с `expression`, который не удаётся разобрать как выражение cron
- **THEN** запись не сохраняется, клиент получает ответ с кодом 400

### Requirement: Удаление записи расписания
Динамический ресурс `/api/cron/web-api/delete` SHALL принимать обязательный параметр `id` и удалять запись расписания с этим идентификатором, возвращая пустой ответ. Если запись с указанным `id` не найдена, SHALL быть возвращён код ошибки 500. После успешного удаления кэш расписания SHALL быть сброшен.

#### Scenario: Удаление существующей записи
- **WHEN** выполняется запрос `/api/cron/web-api/delete` с `id` существующей записи
- **THEN** запись удаляется, кэш расписания сбрасывается, клиент получает пустой ответ без ошибки

#### Scenario: Удаление несуществующей записи
- **WHEN** выполняется запрос `/api/cron/web-api/delete` с `id`, для которого нет записи расписания
- **THEN** клиент получает ответ с кодом 500

### Requirement: Проверка и описание выражения
Динамический ресурс `/api/cron/web-api/describe` SHALL принимать обязательный параметр `expression` и возвращать объект с полями `valid` (признак того, что выражение разобрано тем же парсером, который исполняет расписание) и `description`. Для некорректного выражения `description` SHALL быть `null`. Для корректного выражения `description` SHALL содержать его человекочитаемое описание на языке системы, либо `null`, если построить описание не удалось.

#### Scenario: Проверка корректного выражения
- **WHEN** выполняется запрос `/api/cron/web-api/describe` с корректным `expression`
- **THEN** в ответе возвращается `valid: true` и человекочитаемое описание выражения на языке системы (или `null`, если описание построить не удалось)

#### Scenario: Проверка некорректного выражения
- **WHEN** выполняется запрос `/api/cron/web-api/describe` с `expression`, который не удаётся разобрать
- **THEN** в ответе возвращается `valid: false` и `description: null`
