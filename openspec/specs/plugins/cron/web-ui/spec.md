# plugins/cron/web-ui Specification

## Purpose

Добавляет в веб-интерфейс раздел для управления расписанием планировщика задач, использующий HTTP API `plugins/cron/http-api`.

## Requirements

### Requirement: Зависимость от HTTP API расписания
`Cron.WebUi` SHALL получать все данные о записях расписания через HTTP API `plugins/cron/http-api`; для корректной работы раздела `Cron.WebUi` SHALL быть подключён вместе с плагином, предоставляющим этот API.

#### Scenario: Раздел использует HTTP API расписания
- **WHEN** пользователь открывает раздел `Cron.WebUi`
- **THEN** данные для раздела запрашиваются через HTTP API `/api/cron/web-api/*`

### Requirement: Раздел расписания
Страница `/cron` SHALL отображать список записей расписания и SHALL предоставлять добавление новой записи, редактирование существующей (открывается кликом по названию записи) и удаление (с подтверждением). Выключенные (`enabled = false`) записи SHALL быть отмечены в списке пометкой.

#### Scenario: Открытие списка записей расписания
- **WHEN** пользователь открывает `/cron`
- **THEN** отображается список записей расписания с возможностью добавить новую, отредактировать или удалить существующую

#### Scenario: Выключенная запись в списке
- **WHEN** в списке есть запись расписания с `enabled = false`
- **THEN** эта запись отмечена в списке пометкой о том, что она выключена

### Requirement: Форма записи расписания
Форма добавления и редактирования записи SHALL позволять задать название (обязательно), выражение cron из пяти сегментов (обязательно) и имя пользовательского сценарного события (необязательно), а также признак активности записи. Под полем выражения и в списке записей SHALL отображаться его человекочитаемое описание, полученное через `describe` HTTP API (см. `plugins/cron/http-api`), а некорректность выражения SHALL быть показана как ошибка поля. Раздел SHALL не содержать собственных знаний о поддерживаемых языках или библиотек разбора cron — проверка формата и построение описания выполняются сервером.

#### Scenario: Ввод корректного выражения
- **WHEN** в форме введено корректное выражение cron
- **THEN** под полем отображается его человекочитаемое описание, полученное с сервера

#### Scenario: Ввод некорректного выражения
- **WHEN** в форме введено выражение, которое сервер признаёт некорректным
- **THEN** поле выражения отображается с ошибкой, и запись не может быть сохранена

### Requirement: Форма записи расписания в шторке
Форма добавления и редактирования записи расписания SHALL открываться в шторке, выдвигающейся с правого края поверх страницы `/cron`, а не на самой странице; список записей SHALL оставаться на странице без изменений. Заголовок шторки SHALL обозначать действие: добавление новой записи или редактирование существующей. Успешное сохранение SHALL закрывать шторку и обновлять список; при ошибке сохранения шторка SHALL оставаться открытой с введёнными данными. Закрытие шторки без сохранения (кнопкой отмены, кнопкой закрытия, клавишей Escape или кликом вне шторки) SHALL отбрасывать введённые данные без подтверждения; при следующем открытии форма SHALL быть заполнена заново.

#### Scenario: Открытие формы новой записи
- **GIVEN** открыта страница `/cron`
- **WHEN** пользователь нажимает кнопку добавления новой записи
- **THEN** справа открывается шторка с пустой формой записи, а список записей остаётся на странице

#### Scenario: Открытие формы редактирования
- **GIVEN** в списке `/cron` есть запись расписания
- **WHEN** пользователь кликает по названию записи
- **THEN** открывается шторка с формой, заполненной данными этой записи

#### Scenario: Успешное сохранение закрывает шторку
- **GIVEN** открыта шторка с корректно заполненной формой
- **WHEN** пользователь сохраняет запись и сервер подтверждает сохранение
- **THEN** шторка закрывается, а список показывает сохранённую запись

#### Scenario: Ошибка сохранения оставляет шторку открытой
- **GIVEN** открыта шторка с заполненной формой
- **WHEN** сохранение завершается ошибкой
- **THEN** шторка остаётся открытой, введённые данные сохраняются, показывается уведомление об ошибке

#### Scenario: Закрытие шторки без сохранения
- **GIVEN** в шторке введены данные новой записи
- **WHEN** пользователь закрывает шторку без сохранения и открывает форму новой записи снова
- **THEN** форма пуста, а запись не создана
