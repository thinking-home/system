# core/plugin-model Specification

## Purpose

Задаёт базовый контракт плагина: жизненный цикл, порядок относительно других плагинов и доступ к инфраструктурным сервисам (логирование, конфигурация, локализация).

## Requirements

### Requirement: Порядок зависимостей плагина
Каждый плагин SHALL получать монотонно возрастающий индекс зависимости (`DependencyIndex`) в момент создания экземпляра, отражающий порядок создания плагинов в процессе.

#### Scenario: индекс возрастает по мере создания плагинов
- **WHEN** создаются несколько экземпляров плагинов один за другим
- **THEN** каждый следующий созданный плагин получает больший `DependencyIndex`, чем предыдущий

### Requirement: Жизненный цикл плагина
Плагин SHALL поддерживать стадии `InitPlugin`, `StartPlugin` и `StopPlugin`; реализация каждой стадии по умолчанию SHALL быть пустой (не бросать исключений) и переопределяться конкретным плагином по необходимости.

#### Scenario: плагин без переопределений проходит все стадии
- **WHEN** плагин не переопределяет ни одну из стадий жизненного цикла
- **THEN** вызов `InitPlugin`, `StartPlugin` и `StopPlugin` не приводит к ошибке

### Requirement: Доступ плагина к инфраструктурным сервисам
При создании контекста плагину SHALL быть присвоены: ссылка на контекст сервисов (`Context`), логгер, именованный по типу плагина (`Logger`), секция конфигурации по полному имени типа плагина в виде `plugins:<FullName>` (`Configuration`) и локализатор строк для типа плагина (`StringLocalizer`).

#### Scenario: секция конфигурации соответствует типу плагина
- **WHEN** плагин обращается к своей секции конфигурации
- **THEN** используется секция `plugins:<полное имя типа плагина>` общей конфигурации приложения

### Requirement: Получение списка всех плагинов в заданном порядке
Контекст сервисов SHALL предоставлять список всех загруженных плагинов, отсортированный по `DependencyIndex` в прямом порядке по умолчанию или в обратном порядке по явному запросу.

#### Scenario: обратный порядок переворачивает список
- **WHEN** список плагинов запрошен в обратном порядке
- **THEN** плагин, созданный последним, оказывается первым в результате
