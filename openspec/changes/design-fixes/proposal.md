## Зачем

Страницы со списками сейчас не различают пустой результат и ошибку загрузки достаточно явно, а заголовки шторок визуально слабо выделены. Изменение делает эти состояния и заголовки единообразными во всех затронутых разделах и закрепляет правила дизайна в проектной документации.

## Границы изменения

### Входит

- Явные центрированные состояния ошибки и пустого списка для пяти асинхронных списков: сценариев, подписок, cron-задач, Telegram-чатов и данных демонстрационной страницы.
- Понятное центрированное пустое состояние для редактируемого списка правил meta-фильтра при сохранении доступного действия добавления строки.
- Увеличенные заголовки всех существующих шторок в интерфейсах плагинов.
- Правила оформления состояний списков и заголовков шторок в проектной документации, включая границы применимости для разных видов коллекций.

### Не входит

- Общий переиспользуемый компонент состояний списка в UI-пакете и его внедрение в плагины.
- Отдельные заглушки для статической навигации, наборов вариантов в полях выбора и вложенных значений одной записи: отсутствие элементов там является обычным состоянием контрола, а не результатом загрузки списка.
- Состояние ошибки для редактируемого списка правил, поскольку его строки хранятся локально и не загружаются отдельно.
- Изменение HTTP API, серверной логики, состава данных списков или поведения форм в шторках.

## Функциональности

### Новые

- `plugins/tmp/web-ui`: явные состояния ошибки и пустых данных для демонстрационной страницы со списком.

### Изменяемые

- `plugins/scripts/web-ui`: явные состояния ошибки и пустого списка для сценариев и подписок, пустое состояние редактируемого списка правил, увеличенный заголовок шторки подписки.
- `plugins/cron/web-ui`: явные состояния ошибки и пустого списка для cron-задач, увеличенный заголовок шторки задачи.
- `plugins/telegram-chat-list/web-ui`: явные состояния ошибки и пустого списка для Telegram-чатов.

## Внешнее влияние

Пользователи затронутых разделов получат единообразную обратную связь при пустых данных и ошибках. Публичные API и форматы данных совместимы; новые зависимости не требуются. Риск реализации и ревью связан с согласованностью пяти асинхронных списков, локального редактора правил и двух шторок, а также с сохранением действующих действий и уведомлений без дублирования или потери информации.

## Расхождения с запросом

- Исходный запрос требовал общий компонент состояния списка. По последующему решению пользователя в текущем изменении состояния собираются отдельно в каждом месте из готовых UI-компонентов; общий компонент в UI-пакете и его внедрение откладываются в отдельное изменение, поскольку исходники общего пакета отсутствуют в этом репозитории и потребовали бы отдельной поставки.
- Ранний Evidence Pack перечислял четыре страницы со списками. Повторная полная проверка по замечанию пользователя выявила пятый асинхронный список на демонстрационной странице; он включён в изменение, потому что для него также применимы состояния пустых данных и ошибки.
