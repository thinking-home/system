## Зачем

Система уже сохраняет чаты Telegram, из которых приходили сообщения, и отдаёт их списком по HTTP, но увидеть эти данные владелец дома может только запросом к API вручную. Из-за этого нельзя посмотреть, кто писал боту и какие чаты известны системе, не выходя из веб-интерфейса. Изменение закрывает этот пробел: добавляет в веб-интерфейс раздел со списком сохранённых чатов.

## Границы изменения

### Входит

- Новый раздел веб-интерфейса, который показывает список сохранённых чатов Telegram со всеми полями записи: идентификатор, логин, идентификатор чата, имя, фамилия, дата.
- Список выводится в порядке убывания даты: сверху самые новые чаты. Порядок фиксирован и задаётся на сервере: HTTP API списка чатов начинает возвращать записи, упорядоченные по убыванию даты, а раздел выводит их в полученном порядке.
- Если сохранённых чатов нет, раздел показывает состояние пустого списка — сообщение о том, что чатов пока нет, вместо пустой области и пустой таблицы с заголовками колонок.
- Раздел получает данные через существующий HTTP API списка чатов, без собственного доступа к базе данных.
- Переход в раздел доступен с корневой страницы веб-интерфейса.
- Заголовки и подписи раздела локализованы (английский по умолчанию, русский перевод) — как у остальных разделов веб-интерфейса.
- Поставка: новый раздел подключается к хосту приложения по умолчанию и описан в документации проекта наравне с другими плагинами.

### Не входит

- Пагинация, фильтрация и поиск по списку чатов (явно исключены запросом).
- Управление порядком вывода: сортировка по другим полям, переключение направления и запоминание выбора пользователя — порядок по дате задан жёстко на сервере.
- Расширение HTTP API списка чатов и изменение модели хранения чатов: состав полей ответа, их формат и отсутствие параметров запроса (включая параметры сортировки) остаются прежними — меняется только гарантия порядка записей в ответе.
- Редактирование, удаление и любые действия над чатами из интерфейса — раздел только для чтения.
- Переход к списку разделов, который строится автоматически из метаданных веб-интерфейса: ссылка на корневой странице добавляется тем же способом, что и существующие ссылки на разделы.
- Отправка сообщений в чат и любая другая работа с Telegram-ботом.
- Аутентификация и разграничение доступа к разделу: их нет во всём веб-интерфейсе.
- Автоматические тесты клиентской части: в проекте нет раннера для клиентского кода; проверка — сборка, компиляция типов и ручной сценарий в браузере.

## Функциональности

### Новые

- `plugins/telegram-chat-list/web-ui`: раздел веб-интерфейса со списком сохранённых чатов Telegram — отображение всех полей записи о чате, вывод в порядке, полученном от HTTP API списка чатов, зависимость от этого API (`plugins/telegram-chat-list/http-api`), доступность раздела с корневой страницы веб-интерфейса, состояние пустого списка с сообщением и поведение при ошибке загрузки данных.

### Изменяемые

- `plugins/telegram-chat-list/http-api`: ответ списка чатов получает фиксированный порядок — записи возвращаются по убыванию даты, самая новая первой. Состав полей ответа и отсутствие параметров запроса не меняются.

## Внешнее влияние

- Потребители HTTP API списка чатов: в контракте появляется гарантия порядка записей (по убыванию даты). Состав полей, формат ответа и отсутствие параметров запроса прежние, поэтому несовместимых изменений нет: раньше порядок не был определён и полагаться на него было нельзя, а клиенты, сортирующие данные сами, продолжат работать.
- Зависимость поставки: раздел работает только вместе с плагинами, предоставляющими HTTP API списка чатов и отслеживание чатов; по отдельности раздел данных не покажет.
- Веб-интерфейс: появление ссылки на новый раздел затрагивает корневую страницу оболочки. Требования capability `plugins/web-ui/application-shell` и `plugins/web-ui/page-registration` при этом не меняются — используются существующие механизмы регистрации разделов и навигации, а состав ссылок корневой страницы ни одним требованием не описан.
- Состав поставки: в приложении по умолчанию появляется ещё один плагин; администраторы с собственным списком подключаемых плагинов должны добавить его сами, иначе раздел не появится. Обратной несовместимости нет.
- Сторонние потребители NuGet-пакетов и авторы плагинов не затронуты.
