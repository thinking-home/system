## Ручные проверки

Автотестов по дельтам нет (см. `coverage.yaml`): утверждения дельты `plugins/telegram-chat-list/web-ui`
описывают поведение раздела в браузере, а утверждения дельты `plugins/telegram-chat-list/http-api` —
ответ работающего ресурса на живой базе. Тест-раннера для `frontend/**`, браузерных и e2e-тестов,
а также тестов с PostgreSQL в проекте нет (`testing.md`).
Ниже — по одной проверке на каждое утверждение с пометкой `manual`: сначала HTTP API (проверки 1–3),
затем раздел веб-интерфейса (проверки 4–15).

### Общее окружение

1. PostgreSQL: контейнер `postgres` с паролем `123` (строка подключения — в `ThinkingHome.Console/appsettings.json`).
2. `ThinkingHome.Console/appsettings.Development.json` (не в git) при необходимости переопределяет порт и секреты.
3. Сборка: `dotnet build ThinkingHome.sln` из корня репозитория (при чистой сборке — дважды подряд).
4. Запуск: `cd ThinkingHome.Console && dotnet run`; веб-интерфейс на порту из
   `plugins:ThinkingHome.Plugins.WebServer.WebServerPlugin:port` (по умолчанию 8080).
   Ниже адреса пишутся как `http://localhost:8080/…` — подставьте свой порт.
5. В списке `assemblies` должны быть `ThinkingHome.Plugins.TelegramChatList`,
   `ThinkingHome.Plugins.TelegramChatList.WebApi` и `ThinkingHome.Plugins.TelegramChatList.WebUi`.
6. Язык интерфейса задаёт ключ `culture` в `appsettings.json` (в репозитории — `ru-RU`).
7. Тестовые данные (таблица `TelegramChatList_Chat`, колонки `Id`, `Login`, `ChatId`, `Date`, `FirstName`, `LastName`)
   добавляются напрямую в базу, например через `psql` в контейнере:

   ```sql
   -- набор A: три чата с разными датами в произвольном порядке и одна запись с пустыми полями
   insert into "TelegramChatList_Chat" ("Id", "Login", "ChatId", "Date", "FirstName", "LastName") values
     (gen_random_uuid(), 'bravo',  1002, '2026-03-05 09:15:00', 'Борис', 'Белов'),
     (gen_random_uuid(), 'alpha',  1001, '2026-05-20 18:40:00', 'Анна',  'Алексеева'),
     (gen_random_uuid(), 'charlie',1003, '2026-01-02 07:05:00', 'Виктор','Волков'),
     (gen_random_uuid(), null,     1004, '2026-02-11 12:00:00', null,    null);

   -- очистка перед проверками пустого списка
   delete from "TelegramChatList_Chat";
   ```

   Ожидаемый порядок набора A по убыванию `date`: `alpha` (2026-05-20) → `bravo` (2026-03-05) →
   запись с `chatId = 1004` (2026-02-11) → `charlie` (2026-01-02). Даты набора различаются,
   поэтому порядок определён однозначно (при равных датах он не гарантируется — `design.md`, «Риски»).

## HTTP API списка чатов (`plugins/telegram-chat-list/http-api`)

### 1. Список сохранённых чатов › Запрос списка чатов

- Окружение: общее, набор данных A.
- Шаги: выполнить `curl -s 'http://localhost:8080/api/telegram-chat-list/web-api/list'`
  (или открыть этот адрес в браузере).
- Ожидаемый результат: возвращается массив из четырёх объектов — по числу записей в
  `TelegramChatList_Chat`; у каждого объекта есть поля `id`, `login`, `chatId`, `firstName`,
  `lastName`, `date`, и их значения совпадают с записями в базе (`chatId` — число, `id` — Guid,
  `date` — строка даты и времени).

### 2. Список сохранённых чатов › Порядок записей в ответе

- Окружение: общее, набор данных A (в базе записи вставлены не по порядку дат).
- Шаги: выполнить `curl -s 'http://localhost:8080/api/telegram-chat-list/web-api/list'` и прочитать
  значения `date` по порядку элементов массива (при наличии `jq` удобно: `| jq -r '.[].date'`).
- Ожидаемый результат: значения `date` идут по убыванию, первой — запись с самой поздней датой:
  `alpha` (2026-05-20) → `bravo` (2026-03-05) → `chatId = 1004` (2026-02-11) → `charlie` (2026-01-02).
- Дополнительно: повторить запрос 2–3 раза (порядок должен быть тем же) и, при желании, вставить
  запись с более поздней датой — она должна оказаться первой.

### 3. Список сохранённых чатов › Отсутствующие значения полей

- Окружение: общее, набор данных A (запись с `chatId = 1004`, у которой `Login`, `FirstName`,
  `LastName` — `NULL`).
- Шаги: выполнить `curl -s 'http://localhost:8080/api/telegram-chat-list/web-api/list'`, найти
  в ответе объект с `chatId: 1004`.
- Ожидаемый результат: в этом объекте `login`, `firstName`, `lastName` равны `null` (именно `null`,
  а не пустая строка и не отсутствующее поле); остальные поля заполнены.

### 14. Локализация раздела списка чатов › Раздел на русском языке

- Окружение: общее, набор данных A; два прогона — (а) `culture: ru-RU` в `appsettings.json`,
  (б) `culture: en-US` в `appsettings.json` — проверка клаузы требования «язык текстов по умолчанию —
  английский». Ключ `culture` в прогоне (б) должен быть задан явно, удалять его нельзя: без ключа
  культура инвариантная, оболочка получает пустой `lang` и раздел не отрисовывается вовсе.
- Шаги: для каждого прогона задать `culture`, перезапустить хост, открыть `/telegram-chat-list`.
- Ожидаемый результат:
  - прогон (а), `ru-RU`: заголовок раздела и подписи полей списка — на русском языке; английских строк
    из кейсета по умолчанию на экране нет;
  - прогон (б), `en-US`: заголовок раздела и все шесть подписей колонок — английские и совпадают со значениями
    соответствующих ключей кейсета `frontend/lang.ts` (например, подпись колонки `chatId` — английское значение
    ключа `chatId` из кейсета, а не русское «ID чата»); русских строк в разделе нет. Сообщение пустого списка
    (`emptyList`) в этом прогоне на экране не появляется — окружение проверки набор данных A, таблица непустая
    (`design.md`, D5), поэтому его язык здесь не проверяется: он проверяется на русском в проверке 15.
- Примечание: согласованность кейсета и `Lang/TelegramChatListWebUiPlugin.resx` показывают русские прогоны —
  проверки 14«а», 15 и уведомление об ошибке в проверке 12. Прогон (б) о ней ничего не говорит: при
  отсутствующем в `.resx` ключе на экран попадает английский текст из кейсета, и английский прогон
  выглядит успешным.
