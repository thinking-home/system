## Общая картина

Две независимые части.

1. Формы в шторке. Пользователь открывает `/cron` или `/scripts/subscriptions` и нажимает кнопку «новая запись» или «новая подписка» (в `/cron` ещё можно кликнуть по названию записи). Сейчас эта кнопка переключает `formVisible`, и форма встаёт над таблицей. После изменения тот же `formVisible` управляет `opened` у `Drawer` из `@mantine/core`, а поля формы переносятся внутрь `Drawer` без изменений. Таблица рендерится всегда. `onClose` у шторки вызывает существующий `resetForm`. `Drawer` приходит из vendor-модулей оболочки, поэтому в оболочке и во всех UI-плагинах обновляется `@thinking-home/ui` до 0.13.0 (vendor Mantine 9.5 с рабочими порталами).
2. Кэш переводов. Оболочка запрашивает `GET /api/webui/lang?id=<localizerId>` для каждого раздела. `HomePluginsMiddleware` строит ключ кэша из пути и `Accept-Encoding`, поэтому все `id` получают одну запись кэша. После изменения в ключ добавляется `Request.QueryString`.

```
кнопка / клик по названию → formVisible=true → <Drawer opened> [поля формы] → submit → API
                                                   ↑ onClose/cancel → resetForm (formVisible=false, поля очищены)
main.js → GET /api/webui/lang?id=X → HomePluginsMiddleware → cacheKey = path + query + Accept-Encoding → WebUiPlugin.GetLang
```

## Единообразие

- Образец: `ThinkingHome.Plugins.Cron.WebUi/frontend/tasks.tsx` (state-машина формы `formVisible`/`editingId`/`resetForm`/`submit`/`fail`).
- Новый модуль: — (новых модулей, пакетов и плагинов нет).
- Места подключения образца: `ThinkingHome.Plugins.Cron.WebUi/CronWebUiPlugin.cs`, `ThinkingHome.Plugins.Scripts.WebUi/ScriptsWebUiPlugin.cs`; регистрация разделов не меняется.
- Исключения подключения: — .

Обе формы получают одинаковую обёртку: `Drawer` с `position="right"`, `title` и `onClose={resetForm}`; внутри шторки остаются те же поля и кнопки «сохранить/добавить» и «отмена». Готового образца `Drawer` в проекте нет, так что этот паттерн сам становится образцом. Форма подписки отличается от образца полями `Select` и таблицей фильтра. Это отличие уже было и оправдано набором данных. Ширина шторки: у cron стандартная (`md`), у подписки `lg`, потому что таблица фильтра по meta в стандартную ширину не помещается.

## Контракты

- UI `/cron`: кнопка `newTask` и клик по названию открывают `Drawer`. Заголовок: `t('newTask')` при добавлении, `t('editTask')` при редактировании. Новый ключ `editTask` добавляется в `frontend/lang.ts` («Edit task») и в `Lang/CronWebUiPlugin.resx` / `.ru-RU.resx` («Редактирование задачи»).
- UI `/scripts/subscriptions`: кнопка `newSubscription` открывает `Drawer` с заголовком `t('newSubscription')`. Новых ключей нет.
- Кнопка «новая …» видна на странице всегда (раньше пряталась, пока форма открыта).
- HTTP: `/api/webui/lang` и остальные ресурсы с `isCached: true` кэшируются на сервере отдельно для каждой строки запроса. Формат ответа и заголовки `Cache-Control` не меняются.
- Зависимость: `"@thinking-home/ui": "^0.13.0"` в `package.json` и `package-lock.json` пяти проектов: `WebUi`, `Cron.WebUi`, `Scripts.WebUi`, `TelegramChatList.WebUi`, `Tmp`.

## Решения

### D1. Шторка оборачивает существующую форму

- Решение: `Drawer` управляется существующим `formVisible`, `onClose` вызывает `resetForm`, `submit` при успехе вызывает `resetForm`, как и сейчас.
- Обоснование: минимальная правка. Поведение успеха и ошибки («Ошибка сохранения оставляет шторку открытой») уже заложено в `submit`/`fail`.
- Альтернативы: вынести форму в отдельный компонент или `useDisclosure`. Отклонено: это рефакторинг вне объёма.
- Последствия: закрытие любым способом отбрасывает данные без подтверждения (требования «Форма записи расписания в шторке», «Форма подписки в шторке»).
- promote: false

### D2. Шторка справа

- Решение: `position="right"`.
- Обоснование: такая шторка редактирования привычна, а слева навигация оболочки.
- Альтернативы: слева (умолчание Mantine) или `Modal`. В запросе указана шторка.
- Последствия: зафиксировано в требованиях дельт.
- promote: true (стоит сделать правилом для будущих форм редактирования)

### D3. Ключ кэша включает сырую строку запроса

- Решение: `cacheKey = "{guid}:{path}{QueryString}:{acceptEncoding}"`, где `QueryString` берётся из `context.Request.QueryString.Value` как есть.
- Обоснование: так же различают URL браузер и клиентский кэш. Ответ обработчика зависит только от параметров запроса.
- Альтернативы: нормализовать порядок параметров. Отклонено: сложнее и выигрыша не даёт, клиент всегда шлёт один формат. Сбрасывать кэш `lang` тоже отклонено: производительность упадёт.
- Последствия: разные порядок и регистр параметров дают разные записи кэша. Объём кэша растёт пропорционально числу разных URL. Для `lang` это число разделов.
- promote: false

### D4. Обновить th-ui во всех пяти проектах одновременно

- Решение: поднять `@thinking-home/ui` до `^0.13.0` через `npm install @thinking-home/ui@^0.13.0` в каждом проекте, чтобы синхронизировать lock-файлы.
- Обоснование: разделы берут Mantine и React из vendor-модулей оболочки. Разные версии `th-build` и vendor грозят рассинхроном import map, к тому же lock-файлы уже расходятся с `node_modules`.
- Альтернативы: обновить только оболочку и два плагина. Отклонено: `TelegramChatList.WebUi` и `Tmp` остались бы на 0.11.0.
- Последствия: пересобираются все UI-бандлы (при чистой сборке дважды).
- promote: false

## Соответствие правилам

- Вендоринг через `SHARED_EXTERNALS`: `Drawer` импортируется из `@mantine/core` как внешний модуль и в бандл раздела не попадает.
- Границы модулей: исправление кэша делается только в `ThinkingHome.Plugins.WebServer`, прикладные плагины не затрагиваются.
- Тексты UI: новый ключ в `Keyset('en', …)` и обоих `.resx`.
- «Собирать дважды»: после обновления th-ui проверять только после второй сборки.

## Риски и компромиссы

- Между 0.11 и 0.13 th-ui может нарушить совместимость API (`createModule`, `useAppContext`, `th-build`). Мера: `npx tsc` во всех UI-проектах и проверка всех разделов в браузере.
- Порталы `Drawer` в 0.13.0 могут не работать (это не подтверждено changelog). Мера: проверка в браузере до гейта. Если не заработает, реализация останавливается с блокером.
- Кэш растёт при запросах с произвольными query. Мера: срок жизни записи 2 ч уже задан, кэшируемых ресурсов с query мало (сейчас один).

## Стратегия проверки

- unit (C#, `ThinkingHome.Tests`): `HomePluginsMiddleware` с `DefaultHttpContext`, `MemoryCache` и фиктивным кэшируемым обработчиком. Покрывает сценарии «Кэшируемый ресурс с разными параметрами строки запроса» и «Повторный запрос с той же строкой запроса». Нужен `ProjectReference` на `ThinkingHome.Plugins.WebServer`.
- Типы: `npx tsc -p tsconfig.json` в `Cron.WebUi`, `Scripts.WebUi`, `TelegramChatList.WebUi`, `Tmp`, `WebUi`.
- Сборка: `dotnet build ThinkingHome.sln` дважды.
- Браузер (`sbox-browser`, порт 8090): сценарии шторки в `/cron` и `/scripts/subscriptions`, переводы `ru-RU` в разных разделах, беглый обход остальных разделов после обновления th-ui.

## Миграция и откат

Миграций данных нет. Откат делается возвратом коммита: версии в `package.json`/lock, `tasks.tsx`, `subscriptions.tsx`, ключ кэша. Серверный кэш в памяти очищается при перезапуске.
