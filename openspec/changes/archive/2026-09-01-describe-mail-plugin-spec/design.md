## Context

`Mail` — следующий по очереди плагин после `Cron`/`Cron.WebApi`/`Cron.WebUi` (см. `proposal.md — Why`). Он не зависит от других плагинов системы, кроме `Scripts` (атрибут `[ScriptCommand]`, тип `Buffer` для передачи бинарных данных из сценария), контракт которого уже специфицирован в `plugins/scripts/script-execution`.

## Goals / Non-Goals

**Goals:**
- Зафиксировать наблюдаемое поведение `MailPlugin` (конфигурация SMTP-соединения, формирование и отправка письма, письма с вложениями, обработка ошибок отправки) как baseline-спецификацию.

**Non-Goals:**
- Изменение кода плагина — документируется поведение as-is.
- Повторное описание контракта `[ScriptCommand]` — он уже специфицирован в `plugins/scripts/script-execution`; спецификация `Mail` только ссылается на него.
- Приём входящей почты — плагин реализует только отправку.

## Decisions

- **Одна capability `plugins/mail/mail-sending`.** У `Mail` единственный публичный контракт — две скриптовые команды отправки почты и связанная с ними конфигурация; отдельных связанных плагинов (как `WebApi`/`WebUi` у `Scripts`/`Cron`) у `Mail` нет.
- **Ошибки отправки не пробрасываются вызывающему сценарию.** `SendMailInternal` перехватывает любое исключение при подключении/отправке, логирует его и не пробрасывает дальше — с точки зрения сценария вызов `sendMail`/`sendMailWithAttachment` всегда завершается без ошибки, независимо от результата отправки. Это фиксируется как наблюдаемое поведение, а не переосмысливается.
- **Аутентификация SMTP — опциональна и определяется по наличию логина и пароля.** Плагин использует `Authenticate`, только если в конфигурации заданы непустые `auth.login` и `auth.password`; в остальных случаях выполняется анонимное подключение.

## Risks / Trade-offs

- Спецификация написана по чтению кода без тестов и README плагина (ни того, ни другого в репозитории нет) — возможны расхождения в неочевидных деталях (например, точный набор параметров SSL/сертификатов у MailKit). Митигация: формулировки ограничены поведением, видимым в коде плагина, без домыслов о внутренностях MailKit.
