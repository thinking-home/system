## Context

`Timer` — следующий по очереди плагин после `WebServer`/`WebServer.UrlValidation` (см. `proposal.md — Why`). Он не зависит от других плагинов и опирается только на инфраструктуру ядра — модель плагина (`core/plugin-model`, `FindMethods`) и изоляцию ошибок обработчиков событий (`core/event-dispatch`, класс `EventContext`, который использует `InternalTimer`). От `Timer` в дальнейшем будут зависеть плагины, которым нужен периодический вызов кода (например, Cron).

## Goals / Non-Goals

**Goals:**
- Зафиксировать наблюдаемое поведение `TimerPlugin` (регистрация обработчиков атрибутом `[TimerCallback]`, вычисление задержки и интервала, старт/остановка вместе с жизненным циклом плагина, передача текущего времени, изоляция ошибок) как baseline-спецификацию для будущих плагинных changes.

**Non-Goals:**
- Изменение кода плагина — документируется поведение as-is.
- Повторное описание изоляции ошибок обработчика — она уже специфицирована в `core/event-dispatch`; спецификация `Timer` только ссылается на неё.
- Спецификации плагинов, использующих `Timer` (Cron и др.) — выносятся в отдельные последующие changes.

## Decisions

- **Одна capability `plugins/timer/callback-scheduling`.** У `Timer` единственный публичный контракт — атрибут `[TimerCallback]` и связанное с ним поведение; связанных плагинов, требующих отдельной capability (как `UrlValidation` у `WebServer`), у `Timer` нет.
- **Изоляция ошибок обработчика — ссылка на `core/event-dispatch`, а не повтор требования.** `InternalTimer` вызывает обработчик через `EventContext<TimerCallbackDelegate>.Invoke()` — тот же механизм, что уже специфицирован в `core/event-dispatch` («Изоляция ошибок при вызове обработчика»). Чтобы не дублировать и не разойтись формулировками, спецификация `Timer` фиксирует только факт применения этого контракта к таймерам, а не переописывает его.
- **Диапазон случайной задержки — `[0, interval)`.** Код использует `random.Next(interval)`, что для `Random.Next(int)` в .NET возвращает значение из `[0, interval)`. Зафиксировано явно, чтобы не оставлять диапазон неоднозначным.

## Risks / Trade-offs

- Спецификация написана по чтению кода и README без тестов плагина (тестов на `Timer` в репозитории нет) — возможны расхождения в неочевидных деталях. Митигация: формулировки опираются на фактический код и README; при расхождении в будущем — уточняются по факту.
