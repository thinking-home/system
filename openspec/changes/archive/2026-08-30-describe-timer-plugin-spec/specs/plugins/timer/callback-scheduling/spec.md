## Purpose

Описывает контракт `TimerPlugin` — периодический вызов методов-обработчиков плагинов по таймеру, регистрируемых атрибутом `[TimerCallback]`.

## ADDED Requirements

### Requirement: Регистрация обработчиков атрибутом `[TimerCallback]`
Плагин SHALL при инициализации найти во всех загруженных плагинах методы, отмеченные атрибутом `TimerCallbackAttribute`, и зарегистрировать для каждого найденного метода отдельный таймер. Сигнатура метода SHALL соответствовать делегату `TimerCallbackDelegate(DateTime now)`.

#### Scenario: метод отмечен атрибутом `[TimerCallback]`
- **WHEN** метод плагина отмечен атрибутом `[TimerCallback]` и соответствует сигнатуре `TimerCallbackDelegate`
- **THEN** для этого метода создаётся отдельный таймер

#### Scenario: несколько плагинов с обработчиками
- **WHEN** атрибутом `[TimerCallback]` отмечены методы в нескольких загруженных плагинах
- **THEN** для каждого отмеченного метода каждого плагина регистрируется свой таймер

### Requirement: Параметры интервала и задержки
Атрибут `[TimerCallback]` SHALL принимать обязательный параметр `interval` (интервал в миллисекундах между вызовами) и необязательный параметр `delay` (задержка в миллисекундах перед первым вызовом). Если `delay` не задан, плагин SHALL использовать случайное значение задержки в диапазоне от 0 (включительно) до `interval` (исключительно), чтобы таймеры разных обработчиков не срабатывали одновременно при старте приложения.

#### Scenario: `delay` указан явно
- **WHEN** атрибут `[TimerCallback]` задан с явным значением `delay`
- **THEN** первый вызов обработчика происходит через `delay` миллисекунд после старта плагина, последующие — с интервалом `interval`

#### Scenario: `delay` не указан
- **WHEN** атрибут `[TimerCallback]` задан без значения `delay`
- **THEN** первый вызов обработчика происходит через случайную задержку от 0 до `interval` миллисекунд после старта плагина, последующие — с интервалом `interval`

### Requirement: Жизненный цикл таймеров
Таймеры SHALL начинать отсчёт задержки до первого срабатывания при запуске плагина (`StartPlugin`) и SHALL быть остановлены и освобождены при остановке плагина (`StopPlugin`). До запуска плагина таймеры SHALL не вызывать обработчики.

#### Scenario: запуск плагина
- **WHEN** плагин переходит в состояние запуска (`StartPlugin`)
- **THEN** все зарегистрированные таймеры начинают отсчёт своей задержки и далее вызывают обработчики с заданным интервалом

#### Scenario: остановка плагина
- **WHEN** плагин останавливается (`StopPlugin`)
- **THEN** все таймеры останавливаются и освобождают свои ресурсы, дальнейшие вызовы обработчиков не происходят

### Requirement: Передача текущего времени в обработчик
При каждом срабатывании таймера плагин SHALL вызывать обработчик, передавая ему текущее время (`DateTime.Now`) на момент срабатывания.

#### Scenario: срабатывание таймера
- **WHEN** наступает момент очередного срабатывания таймера
- **THEN** обработчик вызывается с параметром `now`, равным текущему времени на момент срабатывания

### Requirement: Изоляция ошибок обработчика
Вызов обработчика SHALL следовать общему контракту изоляции ошибок для обработчиков событий (см. `core/event-dispatch` — «Изоляция ошибок при вызове обработчика»): исключение внутри обработчика не должно прерывать работу таймера или влиять на срабатывание других таймеров.

#### Scenario: обработчик бросает исключение
- **WHEN** обработчик, вызванный таймером, бросает исключение
- **THEN** исключение логируется, а таймер продолжает срабатывать по расписанию, остальные таймеры не затрагиваются
