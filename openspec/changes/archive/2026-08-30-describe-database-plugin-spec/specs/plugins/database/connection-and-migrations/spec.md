## Purpose

Описывает, как `DatabasePlugin` подключается к СУБД и приводит её структуру в актуальное состояние при старте приложения, до того как другие плагины начинают использовать доступ к данным.

## ADDED Requirements

### Requirement: Обязательная строка подключения
Плагин SHALL читать строку подключения из своей секции конфигурации (параметр `connectionString`, см. `core/plugin-model` — «Доступ плагина к инфраструктурным сервисам») и SHALL прерывать инициализацию с ошибкой, если параметр не задан или пуст.

#### Scenario: строка подключения не задана
- **WHEN** параметр `connectionString` отсутствует или пуст в секции конфигурации плагина
- **THEN** инициализация плагина завершается исключением, и приложение не запускается

#### Scenario: строка подключения задана
- **WHEN** параметр `connectionString` задан
- **THEN** плагин использует его для подключения к СУБД PostgreSQL

### Requirement: Единственная поддерживаемая СУБД
На данный момент плагин SHALL поддерживать только PostgreSQL как целевую СУБД; выбор провайдера БД не настраивается извне. Это ограничение текущей реализации, а не часть контракта, на который могут полагаться другие плагины (см. `plugins/database/data-access-api` — «API не зависит от конкретной СУБД»); в будущем список поддерживаемых СУБД может быть расширен без изменения контракта для плагинов-потребителей.

#### Scenario: попытка подключения к другой СУБД
- **WHEN** строка подключения указывает на СУБД, отличную от PostgreSQL
- **THEN** поведение не специфицировано текущим контрактом — плагин не предоставляет способа выбрать другую СУБД

### Requirement: Применение миграций при старте
При инициализации плагин SHALL применить миграции БД для каждой сборки, содержащей хотя бы один загруженный плагин, ровно один раз на сборку, независимо от количества плагинов в этой сборке.

#### Scenario: несколько плагинов в одной сборке
- **WHEN** несколько загруженных плагинов принадлежат одной и той же сборке
- **THEN** миграции этой сборки применяются один раз, а не по разу на каждый плагин

#### Scenario: миграции применяются до готовности плагина
- **WHEN** приложение стартует и `DatabasePlugin` завершает инициализацию
- **THEN** миграции всех сборок с плагинами уже применены к БД
