## Неблокирующие находки

1. `openspec/changes/chat-list-ui/test-plan.md:168` (проверка 14, окружение прогона «б») — альтернатива «`culture: en-US` (или ключ `culture` удалён)» предлагает два неэквивалентных окружения. При удалённом ключе `HomeConfiguration.GetCulture()` возвращает `CultureInfo.GetCultureInfo("")` — инвариантную культуру (`ThinkingHome.Core.Infrastructure/HomeConfiguration.cs:58-59`), и `/api/webui/meta` отдаёт `config.lang = ""` (`ThinkingHome.Plugins.WebUi/WebUiPlugin.cs:182`). Дальше `Page.tsx:29-32` строит `new I18nContext({locale: lang, …})`, а его конструктор сразу вызывает `new Intl.PluralRules(locale)` (`@thinking-home/i18n/dist/core.js:11`), который при пустой строке бросает `RangeError: Incorrect locale information provided` (проверено в node). Сценарий отказа: проверяющий выбирает «ключ удалён», раздел (как и любой другой раздел оболочки) не отрисовывает тексты, проверка помечается проваленной, хотя клауза «язык текстов по умолчанию — английский» при `culture: en-US` выполняется. Наименьшая правка: убрать из окружения прогона «б» скобку «или ключ `culture` удалён», оставив явный `culture: en-US`. Оракул: при `culture: en-US` раздел открывается и показывает английские тексты кейсета; окружение без ключа `culture` в проверке не используется.
2. `openspec/changes/chat-list-ui/test-plan.md:176-177` (проверка 14, ожидаемый результат прогона «б») — вывод «имён ключей (`title`, `emptyList`, `chatId`) на экране нет, то есть кейсет и `Lang/TelegramChatListWebUiPlugin.resx` согласованы» не следует из наблюдения: `Keyset.getMessage` возвращает `ctx.getMessage(k) || content || k` (`@thinking-home/i18n/dist/core.js:29-31`), то есть при отсутствии ключа в `.resx` на экран попадает английский текст из кейсета, а имя ключа видно, только если ключа нет и в кейсете. Сценарий отказа: реализатор забывает ключ в `Lang/TelegramChatListWebUiPlugin.resx`, прогон «б» проходит (тексты английские — из кейсета), и проверяющий по букве ожидаемого результата фиксирует согласованность, которой нет; расхождение всплывает только на русских прогонах. Наименьшая правка: оставить в прогоне «б» ожидание «тексты английские и совпадают со значениями кейсета», а вывод о согласованности ключей с `.resx` убрать, отнеся его к русским прогонам (проверки 14«а», 15 и уведомление в проверке 12). Оракул: при `culture: ru-RU` ни заголовок, ни подписи колонок, ни `emptyList`, ни `errorLoad` не показываются по-английски — значит все ключи есть в `ru-RU.resx`.
