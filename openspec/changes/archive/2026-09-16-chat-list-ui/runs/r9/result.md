# Результат — planner / plan (r9, возврат по feedback)

## Что сделано

Решение владельца с гейта tests («порядок вывода задаём на сервере: захардкодить сортировку по убыванию `date` в HTTP API списка чатов») проведено по всем артефактам плана.

- **Дельты спецификаций.** Добавлена дельта `openspec/changes/chat-list-ui/specs/plugins/telegram-chat-list/http-api/spec.md`: `MODIFIED` требования «Список сохранённых чатов» — ресурс возвращает список, «упорядоченный по убыванию `date`: запись с самой поздней датой — первой», плюс новый сценарий «Порядок записей в ответе»; оба существующих сценария («Запрос списка чатов», «Отсутствующие значения полей») скопированы из истины без изменений. В `specs/plugins/telegram-chat-list/web-ui/spec.md` требование «Порядок вывода чатов» переписано: раздел выводит чаты в порядке ответа API и не переупорядочивает их (порядок задаёт `plugins/telegram-chat-list/http-api`), средств изменить порядок нет; сценарии заменены на «Список выводится в порядке ответа API» и «Изменить порядок вывода нельзя». Формулировка выбрана по образцу действующей истины `openspec/specs/plugins/cron/http-api/spec.md:16-21` («список … упорядоченный по `name`»).
- **proposal.md.** «Входит»: порядок задаётся на сервере. «Не входит»: параметры сортировки в API по-прежнему не появляются, меняется только гарантия порядка. Раздел «Функциональности → Изменяемые» больше не пустой: `plugins/telegram-chat-list/http-api` (фиксированный порядок ответа). «Внешнее влияние»: изменение контракта обратно совместимое — состав полей и параметры прежние, прежний порядок контрактом не задавался.
- **design.md.** D3 переписан: `OrderByDescending(x => x.Date)` в `TelegramChatListWebApiPlugin.GetChatList` до проекции, клиент не сортирует; отклонённый вариант клиентской сортировки оставлен в альтернативах с пометкой, что он отклонён владельцем. Обновлены «Общая картина» (таблица компонентов: меняется `TelegramChatList.WebApi`, доменный плагин — нет), схема потока данных (`ORDER BY Date DESC`), «Контракты» (раздел HTTP теперь описывает изменение контракта и совместимость), «Соответствие правилам», «Риски» (+3 пункта: изменение работающего API, сортировка без индекса по `Date`, неопределённый порядок при равных датах), «Стратегия проверки» (новый порядок проверяется `curl`, уровень component C# в `testing.md` помечен «—»), «Миграция и откат». Добавлен обязательный раздел «Единообразие» (его не было в прошлой редакции): образцы `Cron.WebUi/**`, `Cron.WebUi/frontend/*`, `Scripts.WebUi/frontend/list.tsx`, `CronWebApiPlugin.GetTaskList`, `Application.tsx` — с перечнем отступлений и причин; серверная сортировка отступлением не является, это повторение приёма из `CronWebApiPlugin.cs:79-83`.
- **tasks.md.** Добавлена группа 1 «Порядок записей в HTTP API списка чатов» (правка `GetChatList` + README плагина `.WebApi`), остальные группы сдвинуты (2–7).
