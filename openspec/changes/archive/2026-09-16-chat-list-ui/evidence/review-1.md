### Проверки по приоритетам

- Спецификация и дизайн. Дельта `http-api` — надмножество истины: оба прежних сценария сохранены дословно, добавлен сценарий порядка; код даёт ровно это. Все 8 утверждений дельты `web-ui` имеют место в коде; сопоставление сделано отдельно по каждому, включая «раздел только для чтения» (в `chats.tsx` нет ни одного обработчика событий, кнопки, формы и модального окна) и «средств изменить порядок нет» (`Table.Th` без `onClick`, сортировки на клиенте нет).
- Логика и пути ошибок. Отказ запроса: `list` остаётся `undefined`, компонент возвращает `null`, список не рисуется, уведомление и запись в журнал клиента есть. Отмена по `AbortSignal` не превращается в ложное уведомление (`if (signal?.aborted) return;`). Повторные вызовы: зависимости `useEffect → load → [api, fail, t]` и `fail → [logger, toaster]` стабильны (`t` мемоизирован в `useKeyset` по `[keyset, ctx]`, `api`/`toaster` — из контекста приложения, `logger` мемоизирован в оболочке), поэтому цикла перезапросов нет; при размонтировании запрос отменяется.
- Форматирование даты. `date` сериализуется `System.Text.Json` в ISO-8601 без смещения — `new Date(...)` разбирает такую строку как местное время, `Intl.DateTimeFormat` вызывается с `lang || undefined`, что снимает падение на пустом языке инвариантной культуры (`CultureInfo.CurrentCulture.Name` у `WebUiPlugin`). Ветка без культуры рассмотрена автором явно.
- Локализация: цепочка рабочая end-to-end — `AddLocalization(opts => opts.ResourcesPath = "Lang")` в ядре, `localizerFactory.Create(type)` для типа `ThinkingHome.Plugins.TelegramChatList.WebUi.TelegramChatListWebUiPlugin` даёт базовое имя ресурса `ThinkingHome.Plugins.TelegramChatList.WebUi.Lang.TelegramChatListWebUiPlugin`, что совпадает с именами встроенных `.resx`; ключи `.resx` и кейсета совпадают один в один (9/9).
- Безопасность и приватность: новых путей нет — раздел только читает существующий ресурс, аутентификации в веб-интерфейсе не было и не появляется, секретов в новых файлах нет, внешних загрузок нет (`@mantine/core`, `react`, `@thinking-home/ui` остаются внешними импортами и резолвятся import-картой оболочки из вендорных модулей `@thinking-home/ui` 0.11.0 — версия пакета одинакова у оболочки и раздела).
- Правила проекта: границы модулей соблюдены (в `.csproj` раздела нет ссылок на `Database` и доменный плагин), схема URL не нарушена (собственных HTTP-ресурсов раздел не регистрирует), `Resources/app/**` не коммитится, имена проекта, класса, раздела и ресурсов соответствуют «Именованию».
- Минимальность: в оболочке изменены ровно три строки, в API — одна строка кода и комментарий; посторонних правок нет. Идентификаторы решения (`ThinkingHome.sln`) уникальны, папка решения та же, что у остальных плагинов.
