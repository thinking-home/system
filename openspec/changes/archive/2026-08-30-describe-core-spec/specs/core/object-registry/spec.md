## Purpose

Предоставляет плагинам потокобезопасные именованные реестры для регистрации команд/обработчиков/объектов конфигурации во время инициализации, а также рефлексивные хелперы для поиска атрибутов и методов-обработчиков в плагинах.

## ADDED Requirements

### Requirement: Реестр «один объект на ключ»
Реестр с одним значением на ключ SHALL хранить не более одного значения на каждый ключ; повторная регистрация значения по уже занятому ключу SHALL приводить к ошибке. Пустой/`null` ключ или `null` значение SHALL игнорироваться без ошибки.

#### Scenario: дублирующийся ключ приводит к ошибке
- **WHEN** значение регистрируется по ключу, который уже занят
- **THEN** регистрация бросает исключение, содержащее значение ключа

#### Scenario: пустой ключ или значение игнорируются
- **WHEN** регистрируется пустой/`null` ключ или `null` значение
- **THEN** регистрация не выполняется и не приводит к ошибке

### Requirement: Регистронезависимость ключей реестра
Ключи реестров SHALL сравниваться без учёта регистра.

#### Scenario: чтение по ключу в другом регистре
- **WHEN** значение зарегистрировано по ключу `"Foo"`
- **THEN** чтение по ключу `"foo"` возвращает тот же элемент

### Requirement: Реестр «список значений на ключ» с неизменяемым снимком
Реестр множественных значений на ключ SHALL накапливать все значения, зарегистрированные по одному ключу, в список; чтение SHALL возвращать неизменяемый снимок списка на момент чтения — последующая регистрация по тому же ключу не должна изменять ранее полученный снимок.

#### Scenario: несколько регистраций по одному ключу накапливаются
- **WHEN** по одному ключу зарегистрированы два значения
- **THEN** чтение по этому ключу возвращает список, содержащий оба значения

#### Scenario: ранее полученный снимок не меняется
- **WHEN** после чтения списка по ключу выполняется ещё одна регистрация по тому же ключу
- **THEN** ранее полученный снимок списка остаётся неизменным

### Requirement: Запрет регистрации после освобождения билдера конфигурации
Билдер конфигурации, построенный поверх реестра, SHALL запрещать регистрацию новых элементов после своего освобождения (`Dispose`), бросая исключение.

#### Scenario: регистрация после Dispose
- **WHEN** элемент регистрируется через билдер после вызова `Dispose`
- **THEN** регистрация бросает `InvalidOperationException`

### Requirement: Поиск атрибутов и методов-обработчиков плагина
Система SHALL по рефлексии находить в плагине методы и типы, помеченные заданным атрибутом, вместе с готовым для вызова делегатом; методы, помеченные атрибутом-обработчиком и одновременно являющиеся `async void`, SHALL быть запрещены — попытка их найти/зарегистрировать SHALL приводить к ошибке до фактического вызова обработчика.

#### Scenario: метод с нужным атрибутом попадает в результат поиска
- **WHEN** метод плагина помечен атрибутом, по которому выполняется поиск
- **THEN** результат поиска содержит этот атрибут, тип и готовый делегат для вызова метода

#### Scenario: async void обработчик запрещён
- **WHEN** метод плагина, помеченный атрибутом-обработчиком, объявлен как `async void`
- **THEN** поиск методов бросает исключение, не дожидаясь фактического вызова такого обработчика
