## Purpose

Описывает механизм декларативной регистрации обработчиков MQTT-топиков другими плагинами через атрибут `[ConfigureMqtt]`, а также регистрацию подписок на топики из конфигурации, инициирующих пользовательские сценарные события.

## ADDED Requirements

### Requirement: Регистрация обработчиков через атрибут `[ConfigureMqtt]`
Плагин SHALL при инициализации найти во всех загруженных плагинах методы, отмеченные атрибутом `ConfigureMqttAttribute` и соответствующие по сигнатуре делегату `ConfigureMqttDelegate` (один параметр — билдер конфигурации, без возвращаемого значения), и вызвать каждый найденный метод с билдером, через который плагин регистрирует свои обработчики топиков.

#### Scenario: Метод с атрибутом ConfigureMqtt вызывается при инициализации
- **WHEN** плагин объявляет метод с атрибутом `[ConfigureMqtt]`, соответствующий `ConfigureMqttDelegate`
- **THEN** при инициализации `MqttPlugin` этот метод вызывается один раз с билдером, через который плагин может зарегистрировать обработчики топиков

#### Scenario: Несколько плагинов с обработчиками
- **WHEN** атрибутом `[ConfigureMqtt]` отмечены методы в нескольких загруженных плагинах
- **THEN** для каждого отмеченного метода вызывается билдер, привязанный к соответствующему плагину-источнику

### Requirement: Регистрация обработчика топика
Билдер конфигурации SHALL предоставлять метод регистрации обработчика по фильтру топика (`RegisterListener(topicFilter, handler)`), принимающий строковый фильтр топика и обработчик, вызываемый с топиком и содержимым (payload) полученного сообщения. Каждой зарегистрированной подписке SHALL присваиваться уникальный числовой идентификатор подписки (`TopicFilterId`), используемый для сопоставления входящих сообщений с обработчиком (см. `plugins/mqtt/broker-connection`).

#### Scenario: Регистрация обработчика с фильтром топика
- **WHEN** плагин вызывает `RegisterListener(topicFilter, handler)` с непустым фильтром топика
- **THEN** обработчик регистрируется под этим фильтром с уникальным идентификатором подписки

#### Scenario: Повторная регистрация того же фильтра топика
- **WHEN** для одного и того же фильтра топика регистрируется обработчик более одного раза
- **THEN** регистрация завершается ошибкой при старте приложения

### Requirement: Регистрация подписок из конфигурации сценарных событий
Плагин SHALL читать из конфигурации секцию `scriptEvents` — словарь пар «фильтр топика → имя сценарного события». Для каждой непустой пары плагин SHALL зарегистрировать обработчик указанного фильтра топика, который при получении сообщения инициирует пользовательское сценарное событие (`ScriptsPlugin.EmitUserEvent`, см. `plugins/scripts/script-events` — «Пользовательское событие») с указанным именем, передавая топик сообщения в meta под ключом `topic` (константа `MqttPlugin.TopicMetaKey`) и содержимое сообщения как `Buffer` (см. `plugins/scripts/script-execution`) вместе с топиком в параметрах события. Пары с пустым или отсутствующим фильтром топика либо именем события SHALL игнорироваться. При регистрации каждой пары плагин SHALL записать в лог связку имени события и фильтра топика.

#### Scenario: Пара фильтр-событие задана корректно
- **WHEN** конфигурация `scriptEvents` содержит пару с непустым фильтром топика и непустым именем события
- **THEN** регистрируется обработчик этого фильтра, инициирующий указанное пользовательское событие при получении сообщения, а связка имени события и фильтра записывается в лог

#### Scenario: Пара с пустым фильтром или именем события
- **WHEN** в конфигурации `scriptEvents` пара содержит пустой (или состоящий из пробелов) фильтр топика либо имя события
- **THEN** эта пара игнорируется, обработчик для неё не регистрируется

#### Scenario: Получение сообщения по подписке из scriptEvents
- **WHEN** приходит сообщение по топику, соответствующему фильтру, зарегистрированному из `scriptEvents`
- **THEN** инициируется пользовательское сценарное событие с указанным именем, meta содержит топик сообщения под ключом `topic`, а параметры события содержат топик и содержимое сообщения как `Buffer`

### Requirement: Секция scriptEvents отсутствует в конфигурации
Если секция `scriptEvents` отсутствует в конфигурации плагина, регистрация подписок из неё SHALL не выполняться, что не влияет на регистрацию обработчиков через `[ConfigureMqtt]`.

#### Scenario: Конфигурация без scriptEvents
- **WHEN** конфигурация плагина не содержит секцию `scriptEvents`
- **THEN** подписки на основе сценарных событий не регистрируются, обработчики, зарегистрированные через `[ConfigureMqtt]`, продолжают регистрироваться как обычно
