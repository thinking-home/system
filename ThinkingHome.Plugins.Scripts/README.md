# ScriptsPlugin

Позволяет сохранять в системе сценарии и выполнять их. Сценарии - небольшие программы на JavaScript, в которых доступен API плагинов. Сценарии могут быть созданы во время работы системы (без необходимости устанавливать или перезапускать что-либо).

## Конфигурация

Вы можете задать максимальное время выполнения сценария в секундах (по умолчанию - 60 секунд). Сценарий, работающий дольше указанного времени, будет прерван с ошибкой. Значение `0` или отрицательное значение отключает ограничение.

```js
{
    "plugins": {

        ...

        "ThinkingHome.Plugins.Scripts.ScriptsPlugin": {
            "executionTimeout": 60
        }
    }
}
```

## Данные

Ниже перечислены классы, определенные в пакете ThinkingHome.Plugins.Scripts для хранения данных о сценариях. Вы можете работать с ними с помощью плагина [DatabasePlugin](../ThinkingHome.Plugins.Database/README.md) и [Entity Framework Core](https://docs.microsoft.com/en-us/ef/core).

### `ThinkingHome.Plugins.Scripts.Model.UserScript`

Представляет собой сценарий, сохраненный в системе.

Таблица: `Scripts_UserScript`

Поля:

- `Guid Id` - id сценария
- `string Name` - название сценария 
- `string Body` - текст сценария

### `ThinkingHome.Plugins.Scripts.Model.ScriptEventHandler`

Содержит информацию о подписке сценария на сценарное событие с заданным именем.

Таблица: `Scripts_EventHandler`

Поля:

- `Guid Id` - id подписки на событие
- `string EventName` - название события
- `string MetaFilter` - фильтр по значениям словаря meta события (см. [фильтры подписок](#фильтры-подписок)); `null` или пустая строка — без фильтра
- `UserScript UserScript` - сценарий, который должен быть выполнен при возникновении события

## API

### `object ExecuteScript(string body, params object[] args)`

Запускает сценарий, текст которого задан первым параметром. Параметры, начиная со второго, передаются в качестве аргументов в запускаемый сценарий.

#### Пример

```csharp
public class MyPlugin : PluginBase
{
    private readonly ScriptsPlugin scripts;
    
    private void MyMethod()
    {
        string script = "var res = 0;" +
            "for (var i = 0; i < args.length; i++)" +
            "res += args[i];" +
            "return res;";

        scripts.ExecuteScript(script, 1, 2, 3, 4, 5, 6);
        
        // result == 15  
    }
}
```

### `object ExecuteScriptByName(string name, params object[] args)`

Запускает сценарий, который был ранее сохранен в системе под именем, указанным первым параметром. Параметры, начиная со второго, передаются в качестве аргументов в запускаемый сценарий. 

#### Пример

```csharp
public class MyPlugin : PluginBase
{
    private readonly ScriptsPlugin scripts;
    
    private void MyMethod()
    {
        scripts.ExecuteScriptByName("switch-on", 42);
    }
}
```

### `[ScriptCommand]`

Вы можете отметить методы своего плагина атрибутом `ThinkingHome.Plugins.Scripts.Attributes.ScriptCommandAttribute` и они станут доступны для вызова из сценариев.

В параметрах атрибута необходимо указать имя, по которому можно будет обращаться из сценария к указанному методу.

Результат работы метода будет передан в сценарий, вызвавший его.

#### Пример

```csharp
[ScriptCommand("мукнуть")]
public int SayMoo(int count)
{
    for (var i = 0; i < count; i++)
    {
        Logger.LogInformation("Му!");
    }

    return 2459 + count;
}
```

## Сценарные события

При возникновении сценарного события автоматически выполняются все сценарии, подписанные на него. Вызов обработчиков происходит асинхронно.

У каждого события есть:

- **название** — константа, которая задается при регистрации события;
- **владелец** — плагин, который зарегистрировал событие; только он инициирует событие (через полученный при регистрации emitter);
- **параметры** — данные для обработчиков; владелец всегда передает в событие один и тот же состав параметров (тип параметров фиксируется при регистрации, состав и значения полей описываются в документации плагина-владельца);
- **meta** — словарь со строковыми значениями, который можно передать при инициации события; подписки могут фильтровать события по значениям meta.

Для сценариев с динамическими именами предназначено [пользовательское событие](#пользовательские-события) — его название `scripts:user-event`, владелец — `ScriptsPlugin`, а произвольное имя передается в meta (ключ `name`).

### `[ConfigureScriptEvents]`

Чтобы зарегистрировать события своего плагина, отметьте метод плагина атрибутом `ThinkingHome.Plugins.Scripts.Events.ConfigureScriptEventsAttribute`. Сигнатура метода должна соответствовать делегату `ConfigureScriptEventsDelegate`: один параметр типа `ScriptEventsConfigurationBuilder`, без возвращаемого значения.

Методы builder:

- `ScriptEventEmitter RegisterEvent(string name)` — регистрирует событие без параметров;
- `ScriptEventEmitter<TArgs> RegisterEvent<TArgs>(string name)` — регистрирует событие, в обработчики которого передаются параметры типа `TArgs`.

Оба метода возвращают emitter — функцию, вызов которой инициирует событие. Emitter принимает параметры события (для generic варианта) и необязательный словарь meta. Вызывать emitter можно после завершения фазы инициализации плагинов (например, из обработчиков `StartPlugin` и любых последующих).

Названия событий не различают регистр и должны быть уникальны в масштабе системы — рекомендуется использовать префикс с названием плагина (например, `noolite:data:received`). Повторная регистрация имени приводит к ошибке при старте приложения.

#### Пример

```csharp
public class MyPlugin : PluginBase
{
    public class MotionEventArgs
    {
        public string RoomName { get; set; }
    }

    private ScriptEventEmitter<MotionEventArgs> motionDetected;

    [ConfigureScriptEvents]
    public void RegisterEvents(ScriptEventsConfigurationBuilder config)
    {
        motionDetected = config.RegisterEvent<MotionEventArgs>("my-plugin:motion-detected");
    }

    private void OnMotionDetected(string roomName)
    {
        motionDetected(new MotionEventArgs { RoomName = roomName });
    }
}
```

### `void EmitUserEvent(string name, params object[] args)`

Генерирует [пользовательское событие](#пользовательские-события) с заданным именем и аргументами. Имя события попадает в meta (ключ `name`), аргументы передаются в обработчики как есть (константа `args` в сценарии-обработчике).

Перегрузка `EmitUserEvent(string name, IReadOnlyDictionary<string, string> meta, params object[] args)` дополнительно принимает словарь meta — его значения будут добавлены в meta события (значение с ключом `name` перезаписывается именем события).

#### Пример

```csharp
public class MyPlugin : PluginBase
{
    private readonly ScriptsPlugin scripts;
    
    private void MyMethod(string roomName)
    {
        scripts.EmitUserEvent("обнаружено-движение", roomName);
    }
}
```

### `ScriptEventDefinition[] GetRegisteredEvents()`

Возвращает список зарегистрированных событий: название, тип плагина-владельца и тип параметров (`null` — событие без параметров).

## API сценариев

### Аргументы и возвращаемые значения

При запуске сценария (как из другого сценария, так и из кода плагинов) ему могут быть переданы аргументы. В каждом сценарии доступна константа `args`, содержащая переданные аргументы: при прямом запуске сценария это массив аргументов, а при запуске обработчиком сценарного события — параметры события (см. [обработчики событий](#обработчики-событий)).

Имя `args` зарезервировано так же, как [meta](#переменная-meta): объявление собственной переменной с таким именем на верхнем уровне сценария приведет к ошибке `SyntaxError`. Встроенный объект JavaScript `arguments` для чтения аргументов сценария не используется.

Также вы можете написать в коде сценария конструкцию `return <возвращаемое значение>;`. После исполнения этой команды выполнение сценария будет закончено, а указанное значение будет передано тому, кто запустил выполнение сценария (в качестве результата работы сценария). 

#### Пример

```js
// считаем сумму переданных аргументов
var res = 0;

for (var i = 0; i < args.length; i++) {
    res += args[i];
}

return res;
```

### Переменная meta

В каждом сценарии доступна константа `meta`. Если сценарий запущен как обработчик сценарного события, она содержит словарь meta этого события (строковые значения); во всех остальных случаях `meta === undefined`.

Имя `meta` зарезервировано: объявление собственной переменной с таким именем на верхнем уровне сценария приведет к ошибке `SyntaxError`, а присваивание значения — к `TypeError`.

#### Пример

```js
if (meta) {
    host.log.info('событие {0}', meta.name);
}
```

### Логирование

Внутри сценариев доступен объект `host.log`, предоставляющий набор методов для логирования: `trace`, `debug`, `info`, `warn`, `error`, `fatal`.

Каждый метод принимает первым параметром сообщение, которое нужно записать в лог, а в качестве остальных параметров можно передать дополнительные аргументы для сообщения. 

Сообщения записываются в лог плагина `ScriptsPlugin` с соответствующим уровнем.

#### Пример

```js
host.log.info('execute script {0}', name);
```

### Методы плагинов

Вы можете вызывать из сценариев методы плагинов, к которым плагины разрешили доступ из сценариев с помощью атрибута [ScriptCommand](#scriptcommand).

Методы плагинов доступны через объект `host.api` под именами, заданными в параметре атрибута `[ScriptCommand]`.

#### Пример

```js
var result = host.api.мукнуть(15); // result === 2474
```

### Запуск других сценариев

Вы также можете запускать из сценариев другие сценарии, обращаясь к ним через объект `host.scripts` по имени, под которым они сохранены в системе.

#### Пример

```js
var result1 = host.scripts.wakeup();
// или
var result2 = host.scripts['покормить кота'](2);
```

### Пользовательские события

С помощью метода `host.emit` вы можете генерировать пользовательские события (событие `scripts:user-event`, см. [сценарные события](#сценарные-события)).

Первым аргументом передается имя события (оно попадет в meta с ключом `name`). Вторым и последующими аргументами можно передать дополнительные данные для обработчиков события.

#### Пример

```js
host.emit('я дома', 35, 4, 'строка текста');
```

### Обработчики событий

В сценарии, запущенном как обработчик события, заполнены обе константы:

- `meta` — словарь meta события (строковые значения);
- `args` — параметры события: для событий плагинов — объект, тип которого зафиксирован при регистрации события (состав полей описан в документации плагина-владельца), для пользовательских событий — массив аргументов, переданных в `host.emit` или `EmitUserEvent`.

#### Пример

```js
// обработчик пользовательского события
host.log.info('событие {0}, аргументы: {1}, {2}', meta.name, args[0], args[1]);
```

### Фильтры подписок

Кроме названия события, в подписке можно задать фильтр по значениям meta — набор пар «ключ-значение». Обработчик будет вызван, если каждая пара фильтра присутствует в meta события (сравнение строк с учетом регистра). Подписка без фильтра срабатывает на все события с заданным названием.

Например, чтобы подписаться на пользовательское событие с именем `я дома`, нужно подписаться на событие `scripts:user-event` с фильтром `name` = `я дома`.

Фильтр хранится в виде строки в формате query string: пары разделены символом `&`, ключ и значение разделены символом `=` и закодированы по правилам URL (`ThinkingHome.Plugins.Scripts.Events.MetaFilter.Serialize`).

### Работа с бинарными данными

Иногда в сценариях нужно работать с бинарными данными. При этом, если передать в сценарий из managed кода массив байтов, то он будет скорвертирован в массив вещественных чисел.

Для работы с бинарными данными используйте специальный класс-обертку `ThinkingHome.Plugins.Scripts.Buffer`. Байты хранятся в его внутреннем поле и тип данных не будет изменен при передаче в сценарии. 

#### Использование

```csharp
public class MyPlugin : PluginBase
{
    private readonly ScriptsPlugin scripts;
    
    private void MyMethod()
    {
        var bytes = ...
        var buffer = new Buffer(bytes);
        
        scripts.EmitUserEvent("my-event", buffer);
    }
}
```

Класс `Buffer` имеет методы для получения находящихся в нем данных в виде массива чисел и в виде строк UTF8 и Base64.

```js
// в обработчике события из примера выше
var buffer = args[0];

// Array<Number>
var bytes = buffer.GetBytes();  
host.log.warn('BYTES: {0}', bytes.join());

// string
host.log.warn('UTF8: {0}', buffer.ToUtf8String());
host.log.warn('BASE64: {0}', buffer.ToBase64String());
```
