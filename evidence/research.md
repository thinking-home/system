## Текущее поведение

- Четыре списка: `/scripts`, `/scripts/subscriptions`, `/cron`, `/telegram-chat-list`; у каждого `useState<…[]>()`, запрос через API и `fail()` с логом/`toaster.showError`. До успешного ответа компонент возвращает `null`; ошибка оставляет это же состояние. Пути: `list.tsx:15-49`, `subscriptions.tsx:30-65,147`, `tasks.tsx:20-53,140`, `chats.tsx:14-36`.
- Пустые ответы отображаются локализованным `<Text>` без центрирования и без общей реализации: `list.tsx:60-79`, `subscriptions.tsx:251-293`, `tasks.tsx:197-237`, `chats.tsx:42-69`; строки определены в трёх `frontend/lang.ts`.
- В кодовой базе ровно две `<Drawer>`: cron и добавление подписки; обе уже открываются справа, а их заголовки передаются как строка `title`. `rg '<Drawer' ThinkingHome.Plugins.*.WebUi/frontend`.
- Browser-наблюдение недоступно: `sbox-browser goto http://127.0.0.1:8080/cron --json` завершилась `EPERM` при создании `/Users/dima117a/.sbox/browser/logs/default.log`; приложение не запускалось.

## Затронутые capability

- `plugins/scripts/web-ui`: требования «Раздел списка сценариев» и «Раздел подписок на события» требуют отображать списки на `/scripts` и `/scripts/subscriptions`; новый контракт состояний списка потребует дельты.
- `plugins/cron/web-ui`: «Раздел расписания» и «Форма записи расписания в шторке»; второе уже фиксирует форму в правой шторке, но не размер её заголовка.
- `plugins/telegram-chat-list/web-ui`: «Отображение незаданных значений и пустого списка» уже требует сообщение при пустом списке, а «Ошибка загрузки списка чатов» — toast без таблицы; требование заглушек уточнит оба состояния.
- `plugins/web-ui/application-shell`: предоставляет разделам `toaster`, тему и локализацию, но не определяет состояния списков. Источники: `openspec/specs/plugins/*/web-ui/spec.md`.

## Границы и владение

- UI-проекты разделов независимы; у всех внешний `@thinking-home/ui`, React и Mantine. Нельзя бандлить общие библиотеки в раздел: `.sbox/project/conventions.md`, «Запрещено».
- Feedback r2 исключает создание и публикацию общего компонента в `@thinking-home/ui`: состояния собираются локально готовыми Mantine-компонентами; будущий общий компонент — отдельное изменение. `openspec/changes/design-fixes/runs/r2/packet.json`, `feedback`.
- Серверные HTTP API и регистрация страниц не требуют изменения: маршруты уже зарегистрированы `CronWebUiPlugin.cs:20`, `ScriptsWebUiPlugin.cs:31-33`, `TelegramChatListWebUiPlugin.cs:20`.

## Доказательства

- `ThinkingHome.Plugins.WebUi/frontend/components/ErrorScreen.tsx` — локальный экран ошибки оболочки красного цвета; не импортируется разделами и не соответствует требуемому серому центрированному состоянию.
- `ThinkingHome.Plugins.{Scripts,Cron,TelegramChatList}.WebUi/frontend/lang.ts` — ключи `emptyList`/`emptySubscriptionList` и `errorLoad`; локализация хранится у каждого плагина.
- `.sbox/project/conventions.md` — UI-тексты через `Keyset`, проверка TS через `npx tsc -p tsconfig.json`; `.sbox/project/testing.md` — браузерных тестов нет, UI проверяется вручную.

## Аналог и единообразие

- Ближайший аналог списка — `ThinkingHome.Plugins.Cron.WebUi/frontend/tasks.tsx`: заголовок, действия, таблица/пустое состояние и `Drawer`; `ScriptList`, `SubscriptionList` и `TelegramChatList` повторяют тот же fetch/fail/`list.length` паттерн.
- Различия: `/scripts/subscriptions` ожидает ещё списки скриптов и событий до рендера; `/telegram-chat-list` только для чтения. Каждый список локально собирает серое центрированное состояние из Mantine и передаёт ему текст своего `Keyset` (решение пользователя в feedback r2).
- Места подключения аналога `CronTaskList` вне его каталога: `openspec/changes/archive/2026-09-26-drawer-for-editors/evidence/research.md` — историческая документация, регистрация не нужна. `git grep -l -F --untracked -- 'CronTaskList'` не нашёл runtime-файлов вне `ThinkingHome.Plugins.Cron.WebUi`.
- Для `SubscriptionList` и `TelegramChatList` все упоминания вне собственных каталогов также исторические/spec-документы либо серверная доменная модель; регистрации нового модуля не требуется. Актуальная регистрация entry/bundle остаётся в соответствующем `package.json` и `*WebUiPlugin.cs`, но список уже является entry и новых маршрутов запрос не добавляет.

## Ограничения и паттерны

- Использовать `Keyset` для английских значений по умолчанию и ресурсные переводы; не вводить UI-тексты напрямую. `.sbox/project/conventions.md`.
- Отмена запроса при размонтировании не считается ошибкой (`signal?.aborted`); это поведение `fail()` надо сохранить во всех страницах.
- Mantine доступен во всех трёх UI-проектах как `@mantine/core@^9.5.1`; заголовок `Drawer` принимает React-узел, поэтому его стиль может быть задан в существующем вызове без серверных изменений (вывод из `tasks.tsx:152-157`, `subscriptions.tsx:165-171`).

## Поверхности изменения и проверки

- Вероятны правки четырёх файлов списков, их `lang.ts` при необходимости новых текстов, и обоих файлов шторок; затем `npx tsc -p tsconfig.json` в каждом изменённом UI-проекте.
- Вероятная поверхность документации — `.sbox/project/conventions.md`; место и формулировка правила дизайна требуют решения планировщика.
- Ручная проверка по `testing.md`: запустить приложение с PostgreSQL, открыть четыре маршрута, проверить пустые ответы и принудительно ошибочный API-вызов; `sbox-browser` в текущей песочнице недоступен.

## Допущения и пробелы

- Не установлено, одинаковы ли тексты пустого и ошибочного состояния для всех списков: feedback r2 определяет визуальные вариации, но не конкретные формулировки. Существующие локализованные `emptyList`/`errorLoad` пригодны как кандидаты; выбор текстов остаётся планировщику.

## Наблюдения вне запроса

- `@thinking-home/ui` не экспортирует компонент состояний (`ThinkingHome.Plugins.WebUi/node_modules/@thinking-home/ui/dist/index.d.ts`); по feedback r2 это не часть текущего объёма, а основание для отдельного изменения пакета.
