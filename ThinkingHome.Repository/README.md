# Локальный репозиторий плагинов

Сервер выдаёт пакеты из одной локальной папки по минимальному профилю NuGet V3. Пакеты добавляются в папку вручную; индекс создаётся при запуске. Подпапки, включая временные каталоги упаковки, не индексируются.

## Запуск

Из корня репозитория после создания пакетов:

```powershell
dotnet run --project ThinkingHome.Repository/ThinkingHome.Repository.csproj -- artifacts/plugin-packages http://127.0.0.1:5088
```

Адрес по умолчанию — `http://127.0.0.1:5088`. Service index доступен по `/v3/index.json`. Для добавления новых пакетов перезапустите сервер. Останавливается он через Ctrl+C.

## Поддерживаемые запросы

Все перечисленные адреса поддерживают GET и HEAD:

| Адрес | Ответ |
|---|---|
| `/v3/index.json` | Service index с ресурсом PackageBaseAddress/3.0.0 |
| `/v3/flat/{lower-id}/index.json` | Нормализованные версии пакета в порядке возрастания |
| `/v3/flat/{lower-id}/{lower-version}/{lower-id}.{lower-version}.nupkg` | Исходные байты пакета, ETag с SHA-512 |
| `/v3/flat/{lower-id}/{lower-version}/{lower-id}.nuspec` | Nuspec из соответствующего пакета |

Отсутствующая версия или пакет возвращают 404. Версии в URL приведены к нижнему регистру, нормализованы по NuGet и не содержат SemVer build metadata. Поиск, registration API, HTTP-публикация и авторизация не реализованы. Для работы через reverse proxy нужна отдельная настройка публичных адресов; текущий service index использует адрес входящего запроса.

## Проверки и неизменяемость

При запуске сервер читает nuspec и сырые PE-метаданные DLL. Проверяются признак плагина, версия формата, обязательные поля, единственность манифеста, совпадение ID и версии с nuspec, наличие объявленных точек входа и зависимостей. Обычная библиотека вместо плагина, повреждённый пакет или конфликт одной identity останавливают индексирование с ошибкой. DLL не загружаются для исполнения; зависимости плагина серверу не нужны.

Это структурная проверка, а не повтор полного анализа API. Доказательство наследования через внешние библиотеки и проверка приватных типов требуют разрешённых зависимостей. Полный валидатор этапа 2 должен повторно применяться после разрешения графа на этапе 4. Сам по себе доступный в репозитории пакет не считается прошедшим эту проверку.

В `.thinkinghome-repository/hashes.json` сохраняется соответствие ID/версия → SHA-512. Если файл опубликованной версии изменён, следующий запуск отклоняет его. Сохраняйте этот каталог вместе с репозиторием: удаление журнала удаляет историю известных хешей. Одновременный запуск двух серверов для одной папки запрещён блокировкой.

Работающий сервер обслуживает снимок байтов в памяти. Изменение исходного файла не меняет уже выдаваемую версию до перезапуска. При неудачном индексировании журнал не фиксируется частично. Удалённый из папки пакет перестаёт выдаваться после перезапуска, но его ранее известный хеш остаётся в журнале.

Текущая реализация предназначена для небольшого локального репозитория: не более 64 MiB на архив и 256 MiB суммарного распакованного содержимого одного пакета; память для снимка требуется пропорционально общему размеру архива пакетов. Лимиты должны учитываться при расширении профиля пакетов.

## Клиент и проверки

[Клиент источников и пример конфигурации](../ThinkingHome.PackageSources/README.md).

```powershell
dotnet test ThinkingHome.Packaging.Tests/ThinkingHome.Packaging.Tests.csproj -m:1 -p:UseSharedCompilation=false -p:NuGetAudit=false
```

HTTP-тест запускает настоящий Kestrel на случайном loopback-порту, получает список версий, скачивает пакет и nuspec, проверяет HEAD, 404 и неизменяемый снимок. Сценарии журнала проверяют запрет подмены версии после перезапуска.

Протокол: [service index](https://learn.microsoft.com/en-us/nuget/api/service-index), [package content](https://learn.microsoft.com/en-us/nuget/api/package-base-address-resource).
