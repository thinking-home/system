# Автоматическое обнаружение точек входа плагина

## Правило

Автор плагина не объявляет список точек входа. Манифест DLL содержит маркер плагина, идентичность, требования к платформе и классификацию зависимостей.

Точки входа — все публично доступные неабстрактные классы-наследники `PluginBase` без открытых generic-параметров, определённые в основной DLL плагина. Учитываются косвенное наследование, закрытые наследники generic-классов и публичные вложенные классы с публичными внешними классами. Зависимости и перенаправленные типы не сканируются. Отсутствие точек входа — ошибка проверки плагина.

Упаковщик и общий планировщик обнаруживают типы через `PluginEntryPoints.Discover` в `MetadataLoadContext`, без выполнения кода DLL. Правило одинаково для установленных пакетов и локальных сборок. Имена сортируются по ordinal-порядку.

Lock-файл хранит вычисленный список, связанный с хешами выбранных DLL. При проверке плана список вычисляется повторно. Хост загружает проверенные типы и передаёт их напрямую в `HomeApplication`; `HomeConfiguration` содержит только настройки. Повторное сканирование для регистрации DI не выполняется.

## Контекст

Разрешению зависимостей нужен согласованный результат обнаружения типов. Выбор автором отдельных классов среди подходящих наследников не является требованием системы.

## Обоснование

Общее правило обнаружения и проверка содержимого DLL обеспечивают согласованность без дублирования структуры кода в авторском манифесте и без генерации списка при сборке.

## Последствия

Каждый подходящий класс основной DLL становится точкой входа выбранного плагина. Для базовых классов следует использовать `abstract`. Маркер плагина остаётся обязательным: обычная .NET-библиотека не становится допустимым корнем менеджера пакетов только из-за наличия наследника `PluginBase`.

## Как проверяется

Тесты сравнивают обнаруженные типы при упаковке, установке и локальном запуске. Проверяются косвенное наследование, вложенные классы, generic-типы, исключение абстрактных и непубличных классов, отсутствие точек входа и анализ без выполнения module initializer. Полный набор проверок поставки: `dotnet test ThinkingHome.Packaging.Tests/ThinkingHome.Packaging.Tests.csproj`.
