# Этап 6: подключение к хосту

ThinkingHome.Console использует один PluginRuntime для установленных пакетов и локальных DLL. Необязательный plugins.local.json объявляет пути и дополнительные корни. Локальный ID имеет приоритет; несовместимость не приводит к fallback. Runtime не скачивает пакеты и не изменяет установленное состояние.

ExecutionPlanner читает DLL-метаданные и стандартный deps.json и передаёт граф общему PlanBuilder/ContractValidator. Библиотеки загружаются непосредственно из результатов Build или установленного хранилища. Платформа, общие контракты, приватная изоляция, DI и жизненный цикл едины для трёх сценариев.

ThinkingHome.Local.proj собирает проекты и генерирует тот же файл подключений. Все 19 плагинов монорепозитория получили метаданные и классификацию зависимостей. Отдельный Development-хост, временная установка разработки и pack-dev удалены. В менеджере пакетов нет специальных режимов локальной разработки.

CLI хоста использует System.CommandLine: декларации `--app` и `--check`, встроенные справка и версия, проверка аргументов до загрузки плагинов. [Параметры запуска](../../ThinkingHome.Console/README.md).

Хост и менеджер поставляются и обновляются совместно, используют одинаковые runtime и платформенные зависимости. Общий `ThinkingHome.Platform.HostPlatform.Current()` вызывается внутри каждого процесса. `platform.json` больше не требуется в командах менеджера; `--write-platform` удалён. [Контракт поставки](../../ThinkingHome.Platform/README.md).

Менеджер формирует appsettings.plugins.json внутри поколения и защищает его хешем. Старые поколения без четвёртого файла поддерживаются. Пользовательская конфигурация не перезаписывается; список assemblies больше не используется хостом.

[Полное описание интеграции, алгоритмов и сценариев для проверки владельцем](../../ThinkingHome.PackageRuntime/README.md). [Результаты проверок](testing.md). Описание актуализировано после обсуждения с владельцем; завершение архитектурной приёмки отдельно не фиксировалось.

Прототип этапа 1 сохранён как исторический эксперимент; рабочий загрузчик имеет собственные проверки EF без подключения к БД. Следующий функциональный этап — удаление и приёмка. Linux, Docker runtime, реальное оборудование и IDE UI отдельно не запускались.

Точки входа обнаруживаются автоматически в основной DLL по [ADR-0004](decisions/ADR-0004-plugin-entry-point-discovery.md); автор не поддерживает отдельный список. Вычисленный список передаётся из загрузчика напрямую в HomeApplication, отдельно от HomeConfiguration.

Классификация зависимостей упрощена по [ADR-0006](decisions/ADR-0006-reference-dependency-policy.md): плагины распознаются по DLL, библиотеки приватные по умолчанию, shared задаётся на обычной ссылке. Проверка утечек приватных типов сохранена.
