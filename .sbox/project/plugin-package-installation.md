# Этап 5: установка и locked-восстановление

Реализован `ThinkingHome.PackageManagement`: `install`, `ci`, `validate`, `recover`, хранилище с дедупликацией по ID/версии, неизменяемые поколения документов и атомарный указатель активного состояния. Форматы декларации, lock и карты сохранены. На этапе интеграции с хостом файл платформы убран из CLI: платформа получается через общий API совместно поставляемых программ. [Команды, структура и API](../../ThinkingHome.PackageManagement/README.md).

Декларация корневых плагинов хранится вместе с lock и картой внутри поколения. `install` меняет корень и пересчитывает граф; `ci` воспроизводит переданный граф без выбора версий. `LockedPlanVerifier` разворачивает точные узлы, повторно проверяет диапазоны, контракты, файлы и привязки и сравнивает результат с lock/картой. Скачивание locked-пакета привязано к записанному источнику.

Проверки завершаются до commit. Журнал позволяет восстановиться после прерывания, а блокировки сериализуют операции и запрещают ремонт используемых файлов. `InstallationSnapshot` удерживает прежнее состояние, пока рядом устанавливается новая версия. Старые версии и поколения остаются на диске. Платформенные сборки предоставляются хостом.

Проверки пятого этапа находятся в `ManagementTests`; проверка pinned-источника — в `SourceTests`. Используются настоящие DLL/nupkg, локальный HTTP и внедрение сбоев на границах фиксации. Возврат после прерывания проверяется подготовкой журнала и резервных каталогов. Результаты запуска — в [testing.md](testing.md).

[Этап 6](plugin-package-runtime.md) подключает загрузчик, удержание снимка, DI и генерируемую конфигурацию. Монорепозиторий и отдельные локальные DLL используют тот же хост через plugins.local.json. Удаление относится к этапу 7. Запуск на Linux, сетевые файловые системы и отключение питания на этом этапе не проверялись.
