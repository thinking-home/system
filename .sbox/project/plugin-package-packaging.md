# Результат этапа упаковки и статической валидации

Второй этап [плана MVP](decisions/ADR-0003-plugin-package-management-stages.md) реализован для одного framework `net10.0` и managed-пакетов. Инструмент, инструкция и ограничения находятся в [ThinkingHome.Packaging](../../ThinkingHome.Packaging/README.md).

## Реализовано

- Общий импорт MSBuild генерирует AssemblyMetadataAttribute из свойств проекта, точек входа, классификации пакетных и встроенных зависимостей. Стандартный NuGet pack создаёт nuspec из тех же PackageId, PackageVersion и ссылок проекта.
- Команда `pack` собирает пакет во временную папку, проверяет его и только после успеха переносит в выходной каталог. Существующая версия не перезаписывается, неудачная операция удаляет только собственные временные файлы.
- Проверяются согласованность DLL и nuspec, разрешённые версии из окружения сборки, точки входа, декларации и состав пакета. Package ID связывается с реальным именем сборки по данным SDK и assets, а не по совпадению строк.
- Контракты читаются через MetadataLoadContext без исполнения кода плагина. Обход включает public/protected поверхность типов, generic-аргументы и ограничения, делегаты, атрибуты с аргументами, поля, базовые типы, интерфейсы, перенаправленные типы и доступные DTO из внешних общих библиотек.
- Неразрешимая ссылка завершает проверку ошибкой. Приватные типы в контракте дают диагностику с цепочкой членов API и владельцем зависимости.
- Доступны команда `validate` и API повторной проверки готового архива с заданным окружением ссылок. На этапе 4 общий ContractValidator также подключён к выбранному графу планировщика.
- Добавлены проекты инструмента и тестов в решение. TimerPlugin подключён как первый реальный пример; runtime-код плагинов и загрузчик не изменялись.

## Проверка 13 октября 2026 года

Windows x64, .NET SDK 10.0.401. Пройдено 31 тест упаковки и валидации, а также 43 существующих теста ThinkingHome.Tests.

Тесты используют настоящие nupkg: корректный плагин с приватной реализацией, пакет с утечками типов, тот же API с общей зависимостью, встроенную библиотеку и транзитивную утечку через внешний DTO. Отдельно проверяются повторные и неизвестные метаданные, неверная точка входа, подмена ID/версии и диапазона зависимости в nuspec, отсутствие ссылки, небезопасные пути архива, сохранение существующего пакета и отсутствие готового пакета после ошибки.

Корректная тестовая DLL содержит module initializer, бросающий исключение при выполнении. Проверка успешно читает её метаданные; DLL не появляется среди загруженных для выполнения сборок тестового процесса.

Успешно создан и проверен `artifacts/plugin-packages/ThinkingHome.Plugins.Timer.4.0.0-alpha34.nupkg`. Пробные пакеты и результаты прогонов удаляются при подготовке к коммиту; они воспроизводятся командами из README и не входят в репозиторий. Публикация не выполнялась. NuGet сообщает о существующем устаревшем licenseUrl в общей конфигурации Package.xml; смена лицензирования не входит в этот этап.

## Пределы результата

Все плагины ещё не мигрированы на формат. Согласование версий и проверку совместимости с конкретной платформой выполняет [планировщик этапа 4](plugin-package-planning.md). Статическая валидация использует восстановленное окружение сборки; она не доказывает отсутствие динамических утечек через object.

Базовая проверка упаковки принимает managed DLL из lib/net10.0. На этапе 4 добавлен приём дополнительных DLL в runtimes/<rid>/lib/net10.0 и runtimes/<rid>/native: конкретные варианты выбирает и повторно проверяет планировщик. Linux-прогон ещё не выполнен. Сервер репозитория, установка и рабочая загрузка не реализуются этим этапом.
