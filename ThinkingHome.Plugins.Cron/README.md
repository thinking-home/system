# CronPlugin

Предоставляет возможность запускать методы плагинов и сценарии автоматизации по расписанию.

## Данные

Плагин добавляет новую сущность `CronTask` для хранения информации о расписании выполнения действий. Данные о расписании хранятся в БД. Вы можете работать с ними с помощью плагина [DatabasePlugin](../ThinkingHome.Plugins.Database/README.md) и [Entity Framework Core](https://docs.microsoft.com/en-us/ef/core).

### `ThinkingHome.Plugins.Cron.Model.CronTask`

Представляет собой одну запись в расписании.

Каждая запись содержит информацию о времени выполнения действия и может содержать имя пользовательского сценарного события. При наступлении нужного времени автоматически будет сгенерировано [пользовательское событие](../ThinkingHome.Plugins.Scripts/README.md#пользовательские-события) с указанным именем (если оно задано) и событие для плагинов.

Таблица: `Cron_Task`

Поля:

- `Guid Id` - id записи.
- `string Name` - название для отображения в интерфейсе (обязательно для заполнения).
- `string EventName` - имя пользовательского сценарного события, которое генерируется при запуске записи расписания (если не указано, событие не генерируется).
- `string Expression` - [выражение cron](#формат-выражения), задающее время запуска.
- `bool Enabled` - признак "запись активна".

### Формат выражения

Время запуска задается выражением cron из пяти сегментов: `минута час день месяц день-недели`. Сегмент может содержать `*` (любое значение), число, диапазон (`1-5`), шаг (`*/5`) и список значений через запятую (`1,15,30`). Например, `*/5 * * * *` — каждые 5 минут, `30 7 * * 1-5` — в 7:30 по будням.

Выражения разбирает и исполняет [NCrontab](https://github.com/atifaziz/NCrontab) — подробности синтаксиса описаны в его документации. Некорректное выражение отклоняется при сохранении через HTTP API, а если такое значение все же попало в БД (например, при ручном редактировании), запись пропускается при загрузке расписания с ошибкой в логе.

Расписание проверяется раз в 20 секунд. Запуски, время которых уже наступило, но не более 5 минут назад (например, если приложение только что запустилось), выполняются при ближайшей проверке.

## API

### `void ReloadTasks()`

Сбрасывает кэш расписания.

При старте приложения плагин загружает из БД информацию о расписании и кэширует её в памяти. Если нужно, чтобы после изменения данных БД новое расписание вступило в силу, необходимо вызвать метод `ReloadTasks()`.

#### Пример

```csharp
public class MyPlugin : PluginBase
{
   private readonly CronPlugin cron;

   private void MyMethod()
   {
      cron.ReloadTasks();
   }
}
```

### `[CronHandler]`

Вы можете отметить методы своего плагина атрибутом `ThinkingHome.Plugins.Cron.CronHandlerAttribute`. Метод вашего плагина будет автоматически вызываться при наступлении времени запуска каждого элемента расписания.

Сигнатура метода, вызываемого по расписанию, должна соответствовать делегату `ThinkingHome.Plugins.Cron.CronHandlerDelegate`:

```csharp
public delegate void CronHandlerDelegate(Guid cronTaskId);
```

#### Параметры:

- `Guid cronTaskId` - id запускаемого элемента расписания.

Плагины могут хранить у себя дополнительную информацию для элементов расписания и использовать её для выполнения действий.

Например, плагин "будильник" может хранить выбранную мелодию будильника и проигрывать её в нужное время.

#### Пример

```csharp
public class MyPlugin : PluginBase
{
    private readonly DatabasePlugin database;

    [CronHandler]
    public void PlayAlarm(Guid cronTaskId)
    {
        using (var db = database.OpenSession())
        {
            var alarm = db.Set<AlarmSettings>().FirstOrDefault(a => a.TaskId == cronTaskId);
    
            if (alarm != null)
            {
                PlayMusic(alarm.Music);
            }
        }
    }
}
```

## Сценарные события

### `cron:task:started`

Сценарное событие `cron:task:started` генерируется при каждом запуске действия по расписанию в дополнение к пользовательскому событию, имя которого указано в записи расписания. Параметров у события нет, а в словаре meta передается значение:

- `taskId` - id записи расписания (строка).

С помощью [фильтра по meta](../ThinkingHome.Plugins.Scripts/README.md#фильтры-подписок) (`taskId` = id записи) подписка может реагировать на запуски только одной записи расписания.

#### Пример обработчика

```js
host.log.info('CRON TASK STARTED: ' + meta.taskId);
```
